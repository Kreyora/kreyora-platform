## Scope completed

Implemented the Instagram connection/credential lifecycle per the approved plan (ADR-014 accepted by owner before build):

1. **Application contracts (Task 1):** `IInstagramGraphClient` (`ValidatePageLinkAsync`, `ValidateAccountAsync`) + `InstagramValidationResult`/`InstagramValidationKind` + pure `InstagramHealthMapper` (validation → Healthy/Active, Expired, Revoked, Degraded policy).
2. **Infrastructure client (Task 2):** `InstagramGraphClient` — first outbound HTTP in the codebase. Bearer-header auth (never in URLs), v21.0 versioned paths (sandbox-proven), timeout/cancellation, error mapping (190→expired, 10→denied, 4/17/32/613→throttled, 5xx/timeout→transient), zero token logging. Registered via `AddHttpClient` + startup-bound `InstagramGraphOptions`.
3. **Lifecycle (Task 3):** `ChannelConnectionService` — Instagram create validates Page-link + account **before** persisting (denial stores nothing); update with new secret = live-validated reauthorize with distinct `integrations.connection.reauthorized` audit; `CheckHealthAsync` branches to the client before the Simulator-only registry (no `IChannelProvider` created; S03 transition recorded in plan). Decrypt failures → Degraded, never throw.
4. **DTOs (Task 4):** `InstagramConnectOptions(PageId, InstagramAccountId)` init-only props on create/update requests; `ExternalAccountId` must equal the IG account ID (deterministic identity rule). No new routes — all 8 existing controller actions suffice.
5. **Tests (Task 5):** 20 unit (`InstagramGraphClientTests`, `InstagramHealthMapperTests` — incl. Bearer/versioning/URL-leak guards), 5 Testcontainers integration (`InstagramConnectionIntegrationTests` — validated create, denial-stores-nothing, reauthorize+audit, expired-health mapping, cross-tenant invisibility) with `FakeInstagramGraphHandler` + `RefusingInstagramGraphClient` for legacy suites. Recorded-safe fixtures only; no real IDs/tokens.

No OAuth server flow (Business Login is client-side — documented N/A with reason). No `debug_token`/app-secret handling (deferred `[UNRESOLVED]`). No webhook/inbox/frontend changes.

## Implementation design

- **Components/modules changed:** Application.Integrations.Instagram (+2 files), Infrastructure.Integrations.Instagram (+3 files), `ChannelConnectionService` (Instagram paths), `ChannelConnectionDto` (options), `DependencyInjection` (options + typed client), 3 legacy test call sites (+1 ctor arg).
- **Runtime or data flow:** Connect: RBAC → duplicate check → live Page-link + account validation → AES-256-GCM encrypt → persist → health record → audit. Health: decrypt → account validation → `UpdateHealth` → persist. Denials return `ValidationError` before any write.
- **Key invariants enforced:** validate-before-persist; secrets encrypted at rest, never returned/logged (DTO unchanged: `HasCredentials`/`KeyVersion` only); tenant filters on every query; no fabricated provider behavior (all mappings from S01-cited docs).
- **Compatibility with prior work:** Backward-compatible; Simulator registry path untouched; no migration.
