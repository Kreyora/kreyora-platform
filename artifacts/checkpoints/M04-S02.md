## Scope completed

Implemented the tenant-scoped inventory foundation: an immutable stock ledger and transactionally maintained per-variant balance. This step intentionally excludes reservations, HTTP APIs, OpenAPI/generated clients, frontend integration, media, checkout, and public-store availability behavior.

## Implementation changes

- Added `InventoryItem` as the materialized balance per tenant and variant, with non-negative on-hand/reserved/threshold invariants and derived available/low-stock values.
- Added immutable `StockMovement` records for opening balance, receipt, corrections, and damage. The `AppDbContext` rejects any update or deletion of a ledger row.
- Added tenant query filters, same-tenant composite foreign keys to Catalog variants and inventory items, a unique inventory item per tenant/variant, a tenant-scoped idempotency-key index, PostgreSQL checks, and `xmin` concurrency on inventory balances.
- Added `IInventoryService` and `InventoryService` for authorized reads, adjustment, movement pagination, low-stock reads, threshold changes, reconciliation, serializable transactions, bounded retry, idempotent replay/conflict handling, and audit evidence.
- Added `AddInventoryLedgerAndBalances` EF migration, including the Catalog alternate key necessary for database-enforced tenant/variant relations.
- Added unit and PostgreSQL integration tests covering core balance rules, append-only protection, adjustment/audit/reconciliation behavior, duplicate replay/key conflict, duplicate opening balance, and tenant isolation.

## Invariants delivered

| Invariant | Enforcement |
|---|---|
| One balance per tenant variant | Unique `(tenant_id, variant_id)` plus a same-tenant composite foreign key. |
| Ledger cannot be altered | Domain has no mutation API; `SaveChangesAsync` rejects modified/deleted `StockMovement` entries. |
| Balance remains valid | Domain and database reject negative on-hand/reserved/threshold states and reserved above on-hand. |
| Stock cannot go negative | The inventory aggregate rejects a signed adjustment that would reduce on-hand below reserved. |
| Adjustment replay is safe | Unique tenant/idempotency key and SHA-256 request fingerprint replay an identical command or conflict on mismatch. |
| Tenant boundary is database-backed | Inventory references Catalog and balance rows through tenant-inclusive foreign keys, filters, and change enforcement. |
| Every committed adjustment is auditable | Adjustment and threshold operations append tenant-scoped audit events in their transaction. |
| Balance can be checked | Reconciliation compares `SUM(stock_movements.quantity_delta)` with materialized on-hand quantity. |
