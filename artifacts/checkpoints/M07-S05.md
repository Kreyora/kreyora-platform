- **Design patterns and data flow:**
  - **Outbox Pattern:** Messages are queued transactionally in `outbound_messages` table and assigned status `Queued`. The background `OutboundDeliveryJob` runs per active tenant using `ITenantJobRunner`, queries due messages (`Queued` or `Failed` with `NextRetryAt <= now`), marks the message `Sending`, executes `IChannelProvider.SendMessageAsync`, records an append-only `OutboundDeliveryAttempt`, and transitions the message to `Sent`, `Failed`, or `DeadLetter`.
  - **Monotonic Provider Status Updates:** Inbound status receipts (`Delivered`, `Read`, `Failed`) match existing outbound messages via the partial index on `(ConnectionId, ProviderMessageId)` and advance the state monotonically: `Sent -> Delivered -> Read`. Stale out-of-order receipts (e.g. `Delivered` arriving after `Read`) are safely ignored without regressing state.
  - **Deduplication & Idempotency:** The unique index on `(tenant_id, connection_id, idempotency_key)` guarantees that identical send requests return the existing message without duplicate provider calls or database entries.
  - **Append-Only Immutability:** `OutboundDeliveryAttempt` entities are recorded once completed; `AppDbContext.EnforceTenantOwnership` explicitly blocks `EntityState.Modified` or `EntityState.Deleted` on attempts.

## Security and tenant isolation

- `OutboundMessage` and `OutboundDeliveryAttempt` implement `ITenantOwned` with global EF Core query filters `e => e.TenantId == CurrentTenantId`.
- Primary keys are ULIDs (`varchar(26)`); foreign keys enforce `(tenant_id, id)` alternate keys to prevent cross-tenant referencing.
- Multi-tenant job execution is bounded by `ITenantJobRunner.RunAsync` with explicit tenant context scopes.
- All controller mutation endpoints require `[Authorize(Policy = TenantPermissions.IntegrationsWrite)]` and anti-forgery tokens.
- All read endpoints require `[Authorize(Policy = TenantPermissions.IntegrationsRead)]`.
- Replay operations require explicit `Idempotency-Key` headers and emit tamper-evident audit records via `IAuditEventService`.
- Append-only constraints in `AppDbContext` reject modification or deletion of delivery attempts.
