## Scope completed

Implemented only M03-S01. The persistence layer now uses ASP.NET Core Identity with a Kreyora application user, and the Domain contains tenant and membership lifecycle models. Tenant creation creates an Owner membership for an existing user. Membership changes enforce the last-active-Owner invariant in serializable transactions. Development-only `--seed` tooling creates roles idempotently and creates demo data only when an environment-supplied password is present.

No browser authentication, API controllers, tenant-context resolution, authorization policies, audit events, or frontend work was added.

## Implementation design

- **Components/modules changed:** Domain tenancy entities and enums; an Application lifecycle-service contract; Infrastructure Identity EF mappings and lifecycle service; Web API development seed hook.
- **Runtime or data flow:** Later authenticated callers can use `ITenantMembershipService` to create a tenant for an existing Identity user or change a membership. The service starts a serializable transaction, counts active Owners when an active Owner would be removed, suspended, or demoted, and rejects the operation if it would leave none.
- **Key invariants enforced:** Tenant slugs are normalized and unique; user names and email addresses are normalized and unique; membership is unique per tenant/user; only Owner, Admin, Operator, and Viewer are tenant roles. `PlatformSupport` is seeded as a global Identity role and is not a tenant-membership role.
- **Compatibility with prior work:** Existing durable-message persistence tables and controlled `--migrate` behavior are preserved. M02 approval was recorded from the user's explicit approval.

## Security and isolation review

- **Authentication/authorization impact:** Introduces persistence and service foundations only. Browser/session authentication and policy enforcement remain deferred.
- **Tenant-isolation impact:** Memberships are tenant-keyed and uniqueness protected; trusted tenant context and query filters are deliberately deferred to M03-S03.
- **Secret/PII/logging impact:** Demo password is read only from `Development__Seed__DemoPassword`; no password is stored in configuration or logged. The local development database connection string is stored in .NET User Secrets, outside Git. `--seed` throws outside Development.
- **Abuse/idempotency/concurrency impact:** Owner-changing lifecycle operations use serializable transactions and reject removal, suspension, or demotion of the final active Owner.
