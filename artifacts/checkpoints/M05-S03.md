# M05-S03 Checkpoint — Customer Contact, Checkout Session, and Reservation

**Status:** `APPROVED`

## Result

M05-S03 converts an existing protected M05-S02 quote into an internal, tenant-scoped, short-lived checkout session. Before creating any hold it recalculates the quote from canonical catalog, publication, inventory, and delivery data. It then allocates every requested inventory line as one serializable PostgreSQL transaction or allocates none. No public route, payment method, order aggregate, or storefront UI wiring was added.

## Scope completed

- Added the optional `Customer` contact profile. Guest checkout retains contact/address only in the checkout-session snapshot; a profile is created or updated only when the caller explicitly opts in to save contact details.
- Added strict Nepal mobile normalization (`9812345678`/`+9779812345678` → E.164) and normalized optional email identity, tenant-scoped uniqueness, privacy acknowledgement fingerprint, and retention-review metadata.
- Added `CheckoutSession`, immutable session line items, session command idempotency, explicit state/timestamps, tenant filters, indexes, `xmin`, and forward-only migration `20260904184445_AddCheckoutSessionsAndCustomers`.
- Added checkout-specific quote-token revalidation. Price, publication, stock, delivery, quote expiry, token integrity, and destination agreement are authoritative server checks before any stock mutation.
- Added `ICheckoutInventoryReservationService` for stable-order multi-line checkout allocation. Inventory remains the owner of balance changes; the CheckoutSession orchestrator owns the serializable transaction across quote, customer, session, idempotency, and holds.
- Added a ten-minute checkout-session configuration and the existing tenant-scoped Hangfire job convention to expire holds and sessions safely.
- Recorded ADR-007 for guest checkout reservation provenance and the cross-module transaction boundary.

Deferred exactly as planned: public store/host resolution and public checkout APIs (M05-S05), customer-facing frontend/cart integration (M05-S06), canonical order/payment creation (M05-S04), customer accounts/address books, and all payment provider work.
