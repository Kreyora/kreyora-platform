# M02-S04 Checkpoint: Aspire, Docker, Local Dependencies, and Developer Workflow

**Status:** COMPLETE
**Date:** 2026-07-27

## Summary

Upgraded Aspire to v13, wired AppHost orchestration for PostgreSQL + API + frontend, added Hangfire background job processing with PostgreSQL storage, created multi-stage Dockerfiles, defined docker-compose configuration, and fixed the pre-existing CSS build issue.

## What was built

### Batch A — Aspire v13 and AppHost orchestration

- **AppHost upgraded** to `Aspire.AppHost.Sdk/13.4.6` (new SDK-style project format)
- **Packages:** `Aspire.Hosting.PostgreSQL` 13.4.6, `Aspire.Hosting.JavaScript` 13.4.6
- **AppHost orchestrates:** PostgreSQL container (persistent lifetime), Kreyora.WebApi (with DB reference), Next.js frontend (via `AddNextJsApp`)
- **DI updated:** `AddInfrastructure()` accepts both `Database:ConnectionString` and Aspire-injected `ConnectionStrings:kreyora`
- **CLI arguments:** `--migrate` runs `MigrationRunner.ApplyMigrationsAsync()` then exits

### Batch B — Hangfire with PostgreSQL storage

- **Packages:** `Hangfire.AspNetCore` 1.8.24, `Hangfire.PostgreSql` 1.21.1 (added to Infrastructure)
- **`HangfireSetup.cs`:** Extension method that configures Hangfire with PostgreSQL storage, conditional on connection string availability
- **Dashboard:** `/hangfire` endpoint mapped only in Development and only when Hangfire services are registered
- **Worker count:** 2 workers configured for background processing

### Batch C — Development seed hook

- **`DevSeedHook.cs`:** Static placeholder method guarded by `IHostEnvironment.IsDevelopment()`
- **CLI trigger:** `--seed` argument in Program.cs invokes seed hook
- **Structured logging** with `LoggerMessage` source generators

### Batch D — Dockerfiles and docker-compose

- **API Dockerfile:** Multi-stage (SDK restore/publish → aspnet runtime), non-root user, port 8080
- **Web Dockerfile:** Multi-stage (pnpm install → Next.js standalone build → runner), non-root user, port 3000
- **docker-compose.yml:** PostgreSQL (16-alpine with health check), API (depends on postgres), web (depends on API), named volume `kreyora_pgdata`, reverse-proxy placeholder
- **docker-compose.override.yml:** Development overrides for environment and ports
- **.dockerignore files:** Root (for web build context), API, and web

### Batch E — Verification and CSS fix

- **CSS build fix:** Root cause identified as `font-[family-name:var(--font-inter),family-name:var(--font-noto-devanagari)]` in `layout.tsx`. Colons inside arbitrary Tailwind values generate CSS selectors (like `.font-\[family-name\:var\(--font-inter\)...`) that postcss can't re-parse within Turbopack's bundled environment. Fixed by removing the problematic class and using `var(--font-inter)` CSS variables directly in `globals.css` body font-family instead.
- **Solution build:** `dotnet build Kreyora.slnx` — 0 errors, 0 warnings
- **Backend tests:** 61 tests pass (36 unit + 6 architecture + 3 contract + 16 integration)
- **Frontend tests:** 482 tests pass (23 test files)
- **API Docker image:** Builds successfully (`kreyora-api:test`)
- **Web Docker image:** Builds successfully (`kreyora-web:test`)

## Key decisions

1. **Aspire.Hosting.NodeJs → Aspire.Hosting.JavaScript:** Package was renamed in Aspire 13; used `AddNextJsApp` (experimental, warning suppressed via `ASPIREJAVASCRIPT001`)
2. **Hangfire dashboard guard:** Service availability check (`JobStorage`) prevents startup crash when no connection string is configured (critical for test host)
3. **Non-root Docker users:** `groupadd`/`useradd` for Debian-based aspnet image, `addgroup`/`adduser` for Alpine-based Node image
4. **Web build context:** Set to monorepo root (`.`) to access `pnpm-lock.yaml` and `pnpm-workspace.yaml`
5. **CSS build fix:** The `font-[family-name:var(--font-inter),...]` arbitrary value class in `layout.tsx` contained colons that generated CSS selectors postcss couldn't re-parse. Removed the class and used `var(--font-inter)` CSS variables directly in `globals.css` body font-family. `postcss.config.mjs` and `@tailwindcss/postcss` are retained (required for both dev and production CSS processing).
