## Scope completed

Implemented the API-independent, tenant-scoped catalog domain. This step intentionally excludes inventory, media, HTTP endpoints, generated clients, storefront projection, and frontend integration.

## Implementation changes

- Added `Product` and `ProductVariant` aggregate rules: normalized tenant-scoped product slugs and SKUs, stable IDs, typed publication states, canonical NPR prices, compare-at price validation, deterministic JSON variant options, and terminal archiving.
- Added PostgreSQL mappings, tenant query filters, database checks, tenant-scoped uniqueness indexes, a composite product/variant foreign key, and PostgreSQL `xmin` optimistic concurrency tokens.
- Added the `AddCatalogProductsAndVariants` EF migration and model snapshot update.
- Added the application catalog contracts and service methods for product/variant changes, publication, archive, authorized reads, idempotent product creation, and typed `Result` outcomes.
- Registered the service; every command requires tenant context and `CatalogWrite`, checks the tenant boundary, records an audit event, and uses a catalog-specific idempotency record for create replay/mismatch protection.
- Added domain unit tests and PostgreSQL integration-test coverage for persistence, audit evidence, idempotent replay, tenant isolation, and tenant-scoped slug/SKU reuse.

| Commands are auditable | Successful catalog commands append tenant-scoped audit events. |
