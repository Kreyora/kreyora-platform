## Implementation Design

- **Components/modules changed:**
  - `Kreyora.Domain`: Added `OrderActions.cs`, `OrderTransitionPolicy.cs`, updated `Order.cs` with state transition methods.
  - `Kreyora.Application`: Extended `OrderContracts.cs` with `IOrderOperationService`, `ExecuteOrderActionRequest`, `OrderOperationResult`.
  - `Kreyora.Infrastructure`: Created `OrderOperationService.cs` implementing authorization, idempotency, concurrency, and audit logging; registered in `DependencyInjection.cs`.
  - `Kreyora.UnitTests`: Added `OrderTransitionPolicyTests.cs` and `OrderAggregateTests.cs`.
  - `Kreyora.IntegrationTests`: Added `OrderOperationServiceTests.cs`.
- **Runtime or data flow:**
  - Seller workspace action request -> `OrderOperationService.ExecuteActionAsync` -> demands role permission (`OrdersWrite` or `PaymentsManage`) -> checks idempotency via `OrderCommand` table -> loads Order entity -> checks `xmin` concurrency token -> evaluates `OrderTransitionPolicy.CanExecute` & validates reason -> executes aggregate method -> records `OrderCommand` -> commits transaction -> appends `IAuditEventService` audit record -> returns `OrderOperationResult`.
- **Key invariants enforced:**
  - Server owns all state transitions; client cannot directly set status values.
  - Merchant QR orders cannot be dispatched until payment is verified and `Paid`.
  - COD orders remain payment `Pending` throughout preparation/dispatch; payment collection requires dispatched or delivered status.
  - Manual payment verification/rejection and COD collection strictly require `PaymentsManage` (Owner and Admin ONLY; Operator is denied).
  - Cancelled orders can never be prepared, dispatched, delivered, or collected.
  - Fulfilled/delivered orders can never be cancelled.
  - Dispatched orders cannot be cancelled directly without recording delivery failure.
  - Mandated reasons for destructive actions (`Cancel`, `RejectPayment`, `MarkDeliveryFailed`) require 3–500 non-whitespace characters.
  - Concurrency token (`xmin`) prevents conflicting concurrent updates.
  - Idempotent command replay returns original outcome; conflicting payload with reused key returns 409 Conflict.
- **Compatibility with prior work:**
  - Preserves all M01–M05 database schemas and existing checkout flows.
  - All 140 solution unit tests, 6 architecture tests, 5 contract tests, and 88 integration tests pass cleanly.
