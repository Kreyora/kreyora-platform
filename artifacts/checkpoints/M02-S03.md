# M02-S03 Checkpoint — PostgreSQL, EF Core, Migrations, and Durable Primitives

**Status:** COMPLETE
**Date:** 2026-07-27

## Summary

Added PostgreSQL persistence infrastructure via Entity Framework Core with snake_case naming conventions, base entities, durable-message primitives, transaction abstraction, and Testcontainers integration tests.

## What was delivered

### Batch A — EF Core packages, DbContext, DesignTimeFactory, snake_case conventions

- Added packages: `Npgsql.EntityFrameworkCore.PostgreSQL`, `Microsoft.EntityFrameworkCore.Design`, `Microsoft.EntityFrameworkCore.Relational`, `EFCore.NamingConventions` to Infrastructure; `Testcontainers.PostgreSql` to IntegrationTests
- `AppDbContext` with `UseSnakeCaseNamingConvention()`, auto-stamp `CreatedAt`/`ModifiedAt` on `SaveChangesAsync`, configurations loaded from assembly
- `DesignTimeDbContextFactory` for `dotnet ef` CLI (reads `DATABASE_URL` env var or falls back to dev defaults)

### Batch B — Base entities and durable-message primitives

- Domain: `BaseEntity` (Id/CreatedAt/ModifiedAt), `ITenantOwned`, `IAuditable`
- Infrastructure entities: `OutboxMessage`, `InboxMessage`, `IdempotencyRecord`
- EF configurations with explicit table/column constraints, unique indexes, and filtered index for unprocessed outbox messages

### Batch C — Transaction abstraction, DI wiring, MigrationRunner

- `IUnitOfWork` in Application (SaveChanges, Begin/Commit/Rollback transaction)
- `UnitOfWork` in Infrastructure wrapping `AppDbContext` transactions
- `DependencyInjection.AddInfrastructure(IConfiguration)` registers `AppDbContext`, `IUnitOfWork` when connection string is configured
- `MigrationRunner.ApplyMigrationsAsync()` for controlled migration execution with structured logging
- Updated `Program.cs` to pass `builder.Configuration` to `AddInfrastructure()`

### Batch D — Migration, Testcontainers, integration tests

- Generated `InitialCreate` migration with three tables: `outbox_messages`, `inbox_messages`, `idempotency_records`
- All columns use snake_case naming (via `EFCore.NamingConventions`)
- `PostgresFixture` using Testcontainers with `postgres:16-alpine`
- 7 persistence integration tests:
  - `MigrationTests`: apply cleanly, idempotent re-apply
  - `TransactionTests`: commit persists, rollback discards
  - `IdempotencyTests`: unique constraint prevents duplicates
  - `OutboxTests`: persist/retrieve, query unprocessed messages

## Key decisions

- Snake_case naming via `EFCore.NamingConventions` rather than manual conventions
- `OnConfiguring` applies snake_case globally so all future entities inherit the convention
- Migrations folder gets its own `.editorconfig` to suppress CA1861 on auto-generated code
- `IUnitOfWork` exposes explicit transaction control rather than ambient transactions
- Testcontainers with real PostgreSQL (not SQLite) for faithful integration testing
- Database connection string is optional — when not configured, DbContext is not registered (allows existing non-DB tests to pass)
