## Scope completed

Implemented `docs/plan/M09-S06_BOUNDED_ORCHESTRATION_PLAN.md` (approved 2026-10-07, "ok implement"; Q1–Q11 as recommended). No live model was called in this step; all tests use the deterministic fake.

1. **`IAssistantTurnService.RunAsync(conversation, triggerMessage)`**: the bounded turn S07 will call.
   1. **Lease:** one turn per conversation, ≤ 2 per shop; a duplicate trigger replays the finished turn.
   2. **Gate:** platform switch, takeover, activation, newer customer message, outside hours (DoNotAnswer), replies per hour.
   3. **Pre-checks without the model:** seller keywords / "talk to a person" → hand-off; a photo without text → the S02 setting.
   4. **Budgets and the data rule** (below).
   5. **Context:**
      - coalesced customer messages since the last handled trigger + up to 20 messages / 6,000 characters;
      - approved knowledge as fenced untrusted data (citations logged); product references from storefront links;
      - prompt **`assistant-system-v1`** (eval-v0 rules + policy + S05 rules; version + template hash logged; per-turn canary).
   6. **Loop:**
      - ADR-020 registry tools under the turn ID (same-turn replay);
      - 3 calls per response, 8 per turn; identical calls refused; malformed/unknown calls get error results;
      - **the last allowed model call has tools switched off**, so the model must answer.
   7. **Output validation:**
      - empty, too long (900), **ungrounded number**, **foreign link** (only this turn's tool links), prompt leak (canary), card/OTP-like digits, tool markup, script;
      - **one corrective retry**, then the safe fallback.
   8. **Ownership re-check:** still automated, no newer customer message.
   9. **Enqueue** through the gated outbox.
2. **Safe fallback (Q3):**
   - `EscalateToHuman` (system takeover) + **one fixed hand-off notice** in the customer's script, at most once per conversation per 12 h;
   - the platform switch, the shop toggle and an existing takeover end **silently**.
3. **Data rule (Q5):**
   - conversation content counts as personal data, so free tiers are refused;
   - only shops on `Ai:DataPolicy:SyntheticTenantIds` reach the model; real shops get the hand-off until you approve a paid no-training provider (ADR-018 unchanged).
4. **Resilience (Q8):**
   - S01's primary → fallback per call;
   - **circuit breaker per model profile** (5 provider failures in 2 min → 5 min open);
   - kill switches: platform, shop, takeover, circuit.
5. **AI action log (`assistant_turns`, Q9):**
   - one row per turn;
   - no prompts, customer/reply text, argument values, keys or reasoning;
   - 90-day daily purge; `GET /v1/assistant/turns` (read).
6. **Owner playground (Q10):** `POST /v1/assistant/playground` (Owner/Admin). Made-up messages run through the real turn with seller-preview tools (dry run); nothing is sent, held or created.
7. **ADR-021** (`Proposed`; your acceptance is part of this review), amending ADR-017 with the `Handoff` origin.

**Deviations and findings:**
- **D1 (fixed latent S02 bug):** the activation query called a staff-permission method (`GetReadinessAsync` demands `storefront.read`). It would have thrown in background turns. It now reads store readiness through a new system-safe `IStoreReadinessQuery` (same readiness rules).
- **D2 (`Handoff` origin, ADR-017 amendment):**
  - a takeover cancels queued automation messages, and the gate refuses automation after it, so the "team member will reply" notice could never arrive;
  - the new `OutboundMessageOrigin.Handoff` gets the full gate (spam, connection, **24 h window**, tested) but is allowed during the takeover it accompanies and isn't cancelled by suppression.
- **D3:** the S01 grounding/language checks moved into Domain (`AssistantText`). The evaluation harness now calls the same code (30 harness tests unchanged and green).
- **D4:** the running turn row is the lease (partial unique index), instead of a PostgreSQL advisory lock. No connection is held for 45 s. Busy results aren't persisted, so S07's retry can run.
- **D5:** the turn row has no `xmin` token. It is written whole at the end, even after other services cleared the change tracker.
- **Bugs caught by the new tests (fixed):**
  1. the context re-read an already handled customer message, because its hand-off notice was queued but not yet in the timeline (now cut at the last handled trigger);
  2. requests shared the live message list (now a snapshot per call);
  3. my OTP pattern missed "my OTP is 482913".

**Integration tests (fake model, real PostgreSQL, turns run as the system):**
- **Happy path:**
  - tools → validated reply → automation outbox message; 3 model calls, 2 tool steps, versions, tokens logged;
  - **the row contains no customer text, reply text, price or product ID**;
  - **no host log line (whole Serilog pipeline) contains customer text, reply text or the canary**;
  - the model received the canary prompt and the customer's text.
- **Duplicate trigger:** replay, one message.
- **Loops:**
  - endless tool calls → 5 calls, last one with tools off → fallback;
  - takeover with category `tool_unavailable`;
  - **the `Handoff` notice stays queued** (not cancelled).
- **Malformed calls:** repeated → `repeated_call`; `MarkPaid` → `tool_not_allowed`; more than 3 → `too_many_calls`; the turn still replies.
- **Hallucinations:**
  - invented price → corrective retry with an explanation;
  - fake tool JSON in the reply → `tool_markup` + `ungrounded_number` → fallback; the invented price is never sent;
  - a foreign link corrected and then sent clean.
- **Provider failure:** 5 × `provider_failure:providerunavailable` → the 6th is `circuit_open` with no call.
- **Slow model:** deadline → fallback within 10 s.
- **Budgets:** per-turn tokens (2 calls then stop), shop daily (1), platform daily (seeded usage), reply rate (skip).
- **Kill switches and ownership:** see the table above; an older trigger → superseded with no call.
- **Data rule:** a real shop on the free tier → 0 model calls, hand-off notice; the phone number never reaches the row.
- **Window:** the hand-off notice is refused outside the 24 h window (`enqueue_denied:window_closed`), but the team still takes over.
- **Pre-checks:** keyword, "talk to a person", photo → no model call; the photo gets the ask-for-details text.
- **Model escalation:** `complaint` category; one notice; a second hand-off within 12 h sends no notice (`fallback_cooldown`).
- **Concurrency:** a running turn → `conversation_busy` (not persisted); 2 running in the shop → `tenant_busy`.
- **Isolation:** another tenant's conversation → `conversation_not_found`; the turn log API is tenant-scoped.
- **Playground:**
  - reply returned; checkout link dry-run; **no outbound, link or takeover**; the row is marked playground;
  - Viewer/Operator 403; a last message from "shop" → 400.

## Security and isolation review

- **Context:** tenant, conversation, store and customer come from server state. Model input is fenced as data. The model can't change tools, budgets or tenant.
- **Privacy (ADR-018):**
  - real conversation content never reaches a free-tier model (tested);
  - the playground is owner-typed synthetic text;
  - the log stores no content (tested on the row and the logs).
- **Sending:** only through the gated outbox. Ownership is re-checked right before enqueueing. Automation stays blocked after takeover; only the single `Handoff` notice passes, and it still obeys the window.
- **Abuse limits:** per-turn, daily and platform caps; reply rate; concurrency leases; circuit breaker.
