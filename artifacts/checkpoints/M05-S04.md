# M05-S04 Checkpoint — Canonical Order and Transactional Creation

**Status:** `REVIEW`

## Result

M05-S04 adds the internal canonical-order conversion that M05-S03 deferred. A verified tenant context can convert exactly one active checkout session into one immutable Order and OrderItems snapshot. The same serializable PostgreSQL transaction commits every linked checkout reservation, completes the session, writes an idempotency command, records a provenance-safe audit event, and emits a minimal `order.created.v1` outbox fact.

No public order controller, host/slug resolution, customer checkout UI, payment configuration/proof, seller order UI, or M06 operational transition was added.

## Scope completed

- Added tenant-scoped `Order`, immutable `OrderItem`, state/payment/fulfilment/source/method enums, and `OrderCommand` idempotency record.
- Added `IOrderCreationService` with a deliberately narrow request: checkout-session ID, payment method, and idempotency key only. Customer, contact, address, delivery, item, price, and financial facts are copied only from the existing checkout-session snapshot.
- Added serializable, bounded-retry orchestration and Inventory-owned batch reservation commitment. On successful conversion, on-hand and reserved balances reconcile; a future cancellation must use an explicit compensating movement rather than releasing committed stock.
- Enforced one order per tenant/session, immutable snapshot relationships, tenant-scoped foreign keys/query filters, `xmin`, append-only command records, and forward-only migration `20260904193957_AddCanonicalOrdersAndCommerceProvenance`.
- Added explicit `CommerceSystem` provenance for guest-safe order audit and stock movements. `ActorUserId` is nullable only for that origin, guarded in domain and PostgreSQL constraints; fabricated seller/system users are prohibited by ADR-008.
- Updated existing seller audit/inventory read compatibility for nullable system actors. The live OpenAPI snapshot and generated TypeScript contract reflect the additive provenance fields, and frontend adapters display `Commerce system` safely.
