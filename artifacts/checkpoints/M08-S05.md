## Scope completed

Implemented `docs/plan/M08-S05_STAFF_REPLY_TAKEOVER_PLAN.md` (owner approval 2026-10-05, "ok implement"; decisions Q1–Q5 as recommended; ADR-017):

1. **Staff reply** — `POST /v1/conversations/{id}/replies`:
   - requires `conversations.write`, antiforgery, and `Idempotency-Key`;
   - creates a pending timeline message and the outbox message atomically;
   - an automated conversation is taken over in the same transaction (Q1, audited with trigger `staff_reply`);
   - same key → same message;
   - one bounded retry if a concurrent change (e.g. an inbound message) wins the conversation row version.
2. **Denials with stable codes** (RFC 7807 `type` = `urn:kreyora:problem:<code>`): `conversation_is_spam`, `connection_inactive`, `capability_unsupported`, `text_required`, `text_too_long` (1,000 characters), `window_closed`, `window_closed_human_agent_unavailable`, `automation_paused_by_takeover`, `invalid_transition`, `conversation_changed`, `assignee_not_member`, `invalid_labels`, `delivery_unconfirmed`.
3. **Delivery:**
   - The Instagram provider sends text via `POST /me/messages` (Page token as a Bearer header, decrypted only in the send path).
   - The outbox re-checks the gate **immediately before `MarkSending`**.
   - Provider-declared transience is honored; a 190 error marks the connection `Expired`.
   - Ambiguous outcomes are never auto-retried.
   - The timeline reconciles: a staff row gets the provider ID and `Sent`, or `Failed` on dead letter; an automation row is added only when accepted.
4. **Takeover / release / assign / unassign / labels / status** routes, with audit on takeover, release, assign, unassign, and status changes.
   - Assignees must be active members of the same tenant.
   - Concurrent edits → `409 conversation_changed`.
   - Status actions (Q3): resolve, reopen, close, mark/unmark spam.
5. **Takeover invariant (ADR-017):**
   - enqueue gate;
   - delivery-time gate (cancels automation that slipped past);
   - `xmin` conflict between a stale delivery's `MarkSending` and the takeover's cancellation;
   - in-flight sends are reported in the audit (`automationMessagesInFlight`), never hidden.
6. **Echoes (Q5):**
   - Instagram-app replies become `ProviderNative` timeline rows (no unread, no window change, no takeover).
   - Echoes of Kreyora sends are ignored.
   - An echo arriving before the send completes is merged into one staff row.
7. **Automation placeholder:** `IConversationReplyService.EnqueueAutomationReplyAsync` (no endpoint; used by the race tests and M09).

**Not done:** internal notes (Q2, deferred); outbound media; profile names; inbox UI (S06); real Instagram sends (S07).

## Deviation from the approved plan

- **No `ProviderPageId` column and no forced reauthorization.** The read-only documentation check (Task 1, below) confirmed the Send API accepts `POST /me/messages` with a Page access token. That call resolves to the token's own Page, so persisting the Page ID and making existing Instagram connections reauthorize were unnecessary. The migration is smaller as a result (no `channel_connections` change). Recorded in ADR-017 §8.

## Implementation design

- **Components/modules changed:**
  - Domain: `OutboundMessageOrigin`; `OutboundMessage.Origin` and `ActorUserId`; `Message` (pending/accept/fail/echo/outbound factories, `OutboundMessageId`, `ActorUserId`); the `Conversation` state machine; echo fields on the v1 payloads.
  - Application: gate (origin, reason codes, tag); `IOutboundEnqueuer`; `IConversationOutboundReconciler`; `OutboundDeliveryResult.IsTransient`; `IInstagramGraphClient.SendTextAsync`; reply and inbox contracts.
  - Infrastructure: `ConversationGate`, `ConversationReplyService`, `ConversationOutboundReconciler`, `ConversationTakeover`, inbox operations, `InstagramGraphClient.SendTextAsync`, provider send and echo, outbox changes, echo ingestion, DI.
  - WebApi: 7 routes.
- **Runtime or data flow:**
  1. Reply → authorize (`conversations.write`) → takeover if automated (cancel queued automation) → `IOutboundEnqueuer` (connection, capability, gate, idempotency; no save) → pending `Message` → one save (with the audit).
  2. Delivery job → gate re-check → `MarkSending` (save; `xmin`) → provider → reconcile timeline → save.
  3. Webhook echo → ingestion → `ProviderNative` row unless the provider ID is already known.
- **Key invariants:**
  - No automation reaches `Sending` after a takeover commits (except a send already in flight, which is reported).
  - At most once on ambiguous provider outcomes.
  - One timeline row per provider message and per outbox message (unique indexes).
  - Every write is tenant-checked and audited where sensitive.
- **Compatibility:**
  - `System`-origin (M07 API) messages bypass conversation rules, so the M07 suites are unchanged.
  - `OutboundMessageService` and `InstagramChannelProvider` gain optional constructor parameters only.
  - `AlwaysAllowConversationGate` is kept for M07 tests; production DI uses `ConversationGate`.
  - The Instagram provider is now registered scoped (the Simulator stays singleton).
  - `IOutboundMessageService.QueueMessageAsync` keeps its `integrations.write` requirement; staff replies use the internal enqueuer under `conversations.write` (Operators lack `integrations.write`).

### Race evidence (forced interleaving, no sleeps)

- **Takeover between the delivery's gate read and `MarkSending`:** an `InterleavingGate` commits a takeover after the gate answered "allowed". The delivery's save then conflicts, the provider is called 0 times, and the final status is `Cancelled`.
- **Automation slipping past the takeover scan:** cancelled at delivery; provider not called.
- **Inbound during a staff reply:** an `InterleavingEnqueuer` commits an inbound update first. The reply retries once and succeeds; unread 2, `LastCustomerMessageAt` updated, one outbox message.
- **Concurrent reassignment:** an interceptor commits B's assignment during A's membership query. A gets `409`; the final assignee is B; exactly one `conversations.assigned` audit entry (B).
- **Echo before send completion:** one timeline row with `Origin = Staff`, the actor, and the provider ID. This confirms EF orders the echo delete before the unique-key update.

## Security and isolation review

- **Authorization:**
  - all 7 routes require `conversations.write` plus antiforgery; replies also require `Idempotency-Key`;
  - Viewer `403`, missing CSRF `400`, cross-tenant `404` on every route (HTTP tests);
  - read-only support is denied at the service.
- **Tenant isolation:** explicit tenant predicates on every query; assignees validated against active memberships of the same tenant (non-member, suspended, or another tenant's member → `assignee_not_member`, nothing written).
- **Secrets:** the Page token is decrypted only in `InstagramChannelProvider.SendMessageAsync` and sent as a Bearer header. Tests assert it never appears in the URL.
- **Audit:** takeover (trigger, cancelled and in-flight counts), release, assigned/unassigned (user IDs), status changes (from/to). No message content.
- **Abuse/idempotency:** reply idempotency key; unique outbox/timeline indexes; at-most-once on ambiguous sends; delivery-time gate.
