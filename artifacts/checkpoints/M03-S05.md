## Implementation design

- Real mode obtains the authenticated user from `GET /v1/auth/me`, lists active workspaces from `GET /v1/workspaces`, and fetches effective permissions only after a workspace is selected.
- The selected tenant ID is stored in `sessionStorage`, so it is isolated per browser tab. Real tenant requests send `X-Kreyora-Tenant-Id`; the API remains the authority for every membership and permission decision.
- Membership APIs grant an existing registered user by email, list members, and invoke the established role/lifecycle service. Server-side Owner/Admin boundaries, transactional audit writes, and final-active-Owner protection remain intact.
- Session expiry clears the workspace/CSRF state and routes to sign-in. An unavailable workspace clears that tab's selection and returns to `/workspaces`; ordinary `403` responses route to `/access-denied`.

## Manual reviewer procedure

1. Start the Development API at `http://localhost:5030` and the web app with `NEXT_PUBLIC_API_URL=http://localhost:5030`.
2. Sign in, open `/workspaces`, select a workspace, and verify `/dashboard` loads. Open a second tab and select another workspace; selections remain independent.
3. As Owner/Admin, open `/team`, add an existing registered email, change/suspend/reactivate/revoke allowed non-Owner memberships, and verify the audit log records the changes.
4. As Viewer/Operator, verify `/team`, `/audit`, and `/billing` redirect to `/access-denied`; API requests remain denied by the backend.
5. Clear or revoke the selected membership and refresh a tenant page; verify the tab returns to `/workspaces`. Sign out and verify sign-in is required again.
