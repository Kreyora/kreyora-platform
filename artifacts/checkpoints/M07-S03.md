- **Runtime or data flow:**
  1. Incoming HTTP webhook request arrives at `WebhooksController`.
  2. Request size (256 KB) and `Content-Type` (`application/json`) limits are enforced.
  3. `WebhookIngressService` resolves `IChannelProvider` from `IChannelProviderRegistry` and `ChannelConnection` from `AppDbContext.ChannelConnections.IgnoreQueryFilters()`.
  4. If connection credentials exist, they are decrypted in-memory using `ISecretEncryptionService`.
  5. `provider.ValidateWebhookAsync` verifies the cryptographic signature (HMAC-SHA256) and replay window.
  6. If invalid: returns 401/400 immediately with redacted diagnostic log; zero database rows created.
  7. Deduplication check: queries `WebhookEvents.IgnoreQueryFilters()` on `(ConnectionId, ProviderEventId)`. If duplicate, returns 200 OK immediately without inserting a row.
  8. Durable storage: establishes tenant context scope via `tenantContext.BeginScope(new TenantContext(connection.TenantId, null, null, null))`, adds `WebhookEvent` with `ProcessingStatus.Received`, and calls `SaveChangesAsync`.
  9. Acknowledges HTTP 202 Accepted immediately (<200ms measured fast path). Downstream normalization and processing are strictly asynchronous (Step 04).
- **Key invariants enforced:**
  - **Durable Fast Path**: Webhook acknowledges immediately after durable raw event storage. No waiting for LLM or downstream processing.
  - **Zero Trusted Events on Invalid Signatures**: Tampered or unauthenticated webhooks are rejected at the edge with zero database rows.
  - **Deduplication**: Composite unique index `(ConnectionId, ProviderEventId)` prevents duplicate event rows. Duplicate deliveries return 200 OK with `isDuplicate = true`.
  - **Tenant Scoping from Connection**: Because webhooks arrive unauthenticated, the tenant boundary is established from the verified `ChannelConnection`.
  - **30-Day Retention Compliance**: Entity includes `IsPurged` and `PurgedAt` per ADR-012.
- **Compatibility with prior work:**
  - Additive migration with 0 pending model changes.
  - Fully compatible with `ChannelConnection` aggregate and existing tenant isolation rules.

## Security and isolation review

- **Authentication/authorization impact:** Endpoints are marked `[AllowAnonymous]` because social providers invoke webhooks without user sessions. Cryptographic signature verification (`X-Hub-Signature-256`) serves as the edge authorization gate.
- **Tenant-isolation impact:** Webhook events are scoped to `connection.TenantId`. Queries on `AppDbContext.WebhookEvents` enforce the global query filter `e => e.TenantId == CurrentTenantId`. Cross-tenant queries return 0 results.
- **Secret/PII/logging impact:** Secrets are never logged or returned in responses. Raw payloads containing customer data are stored per ADR-012 with 30-day purge flags. Log messages use strongly typed `[LoggerMessage]` delegates with correlation IDs and masked values.
- **Abuse/idempotency/concurrency impact:** Payload size limit (256 KB) and content-type enforcement protect against memory attacks. Replay window validation (300 seconds) prevents replay attacks. Unique composite index on `(ConnectionId, ProviderEventId)` prevents duplicate inserts. Shadow `xmin` concurrency token protects against update collisions.

## Decisions and assumptions

- **ADRs created or changed:** Follows accepted `ADR-010` (connection ownership & routing), `ADR-011` (normalized events), `ADR-012` (payload retention & purge), and `ADR-013` (secrets encryption).
- **Assumptions made:** Webhook endpoints accept `application/json` payloads up to 256 KB. Replay window defaults to 300 seconds.
- **External evidence used:** Meta Webhook verification protocol (`hub.mode`, `hub.challenge`, `hub.verify_token`, `X-Hub-Signature-256`).
