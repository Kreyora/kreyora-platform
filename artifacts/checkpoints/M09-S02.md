1. **AssistantPolicy** (one per workspace; safe defaults created on first read):
   - **Defaults:**
     - seller toggle **on** (activation still needs readiness);
     - reply style **match the customer**;
     - languages Nepali, Romanized Nepali and English; tone Friendly;
     - business hours 09:00–19:00 Asia/Kathmandu; outside hours: **answer and promise follow-up**;
     - **unidentified photo or link: ask for details** (M3);
     - read tools plus `EscalateToHuman` (always on); **write tools cannot be enabled before S05**.
   - **Escalation:** the fixed escalation set (customer asks for a person, complaint, refund/exchange, custom/wholesale order, health/safety, legal, payment dispute, abusive message) cannot be switched off, plus ≤ 20 seller keywords.
   - **Budgets:** tool steps 4, replies per conversation per hour 20, output 600, **validated against platform caps** (`Ai:Limits`) and clamped again on read for orchestration.
   - **Brand note:** ≤ 300 characters, no markup.
   - **Concurrency:** optimistic (`xmin`); a stale `version` returns 409 `assistant_policy_changed`.
   - **Audit:** `assistant.policy.updated` records **changed field names only**.
   - **Reviewed marker:** the first save sets `ReviewedAt`, which activation requires (Q8).
2. **Knowledge library**: documents with versions.
   - **Inputs:**
     - pasted text;
     - `.txt` / `.md` upload (UTF-8, ≤ 256 KB, ≤ 30,000 characters; PDF, Word and binaries refused with "paste the text instead"; no URL fetching);
     - **import of the store's Returns / Payment / Terms policies as drafts** (Q7).
   - **Lifecycle:**
     - submit → PendingReview → **Approved = Active** (the previous Active becomes Superseded) or Rejected (with note);
     - **delete** marks all versions Deleted, clears text and **purges uploaded originals** from private storage.
   - **Approval:** Owner/Admin approve; the same person may submit and approve, audited (Q4/Q5).
   - **Retried submissions:** the same `Idempotency-Key` returns the original version.
   - **Database guarantee:** a unique partial index allows **one Active version per document**; the approve flow supersedes first, then activates, in one transaction.
   - **Audit:** submitted / approved / rejected / deleted / imported, with **metadata only (never text)**.
3. **Query contracts for later steps:**
   - `IApprovedKnowledgeQuery`: **only Active versions of non-deleted documents in the current workspace**;
   - `IAssistantPolicyQuery`: effective, clamped policy;
   - `IAssistantActivationQuery`: computed activation.
4. **Readiness** (`GET /v1/assistant/readiness`), computed on read:
   - **required:** `store_ready` (reuses `StoreReadiness.CanAcceptOrders`), `channel_connected`, `policy_reviewed`;
   - **recommended:** `knowledge_approved`;
   - **informational:** `platform_enabled`.
   - **IsActive** = seller toggle AND required checks AND the platform switch.
5. **API:** 12 routes under `/v1/assistant` (policy, readiness, knowledge CRUD / upload / import / approve / reject / delete), RFC 7807 problem codes, antiforgery on writes, `ai.configuration.read/write` permissions (already defined). OpenAPI/TS regenerated (additive).

## Implementation design

- **Domain** (`Kreyora.Domain/Assistant`):
  - `AssistantPolicy`, plus `AssistantPolicyRules` (validation) and the settings and caps records;
  - `KnowledgeDocument`, `KnowledgeDocumentVersion` (state rules), `KnowledgeText` (normalize / extract / validate / hash).
- **Application** (`Kreyora.Application/Assistant/AssistantContracts.cs`): services, query contracts, DTOs, problem codes.
- **Infrastructure** (`Kreyora.Infrastructure/Assistant`): `AssistantPolicyService`, `AssistantReadinessService`, `KnowledgeService`. Storage keys via `ITenantKeyBuilder` (`tenants/{tenant}/assistant-knowledge/{document}/…`).
- **Invariants:**
  - tenant filters plus explicit `TenantId` predicates on every query;
  - only Active versions are retrievable;
  - one Active version per document (database-enforced);
  - text is never logged or audited;
  - only validated plain text is stored;
  - nothing in S02 calls a model.

## Security and isolation review

- **Authorization:** reads need `ai.configuration.read`; writes, approval and deletion need `ai.configuration.write` (Owner/Admin). Antiforgery on all writes.
- **Tenant isolation:** query filters + explicit `TenantId` predicates; object keys carry the tenant; cross-tenant IDs → 404 (tested); retrieval is tenant-scoped (tested).
- **Data handling:**
  - knowledge text never appears in logs or audit (tested for audit);
  - deleted text is cleared and originals purged;
  - only validated UTF-8 text is stored;
  - no model calls in S02;
  - real shop content reaches a model only at activation, on an approved paid endpoint (ADR-018).
- **Abuse:** size and type limits; the brand note is bounded and has no markup; no URL fetching (SSRF); malicious instructions inside documents are tested in S03/S06, where content meets the model.

## Decisions and assumptions

- **ADRs:** none new (ADR-018 governs data handling).
- [ASSUMPTION] Storage purge happens after the database commit. If the storage delete fails, the text is already cleared in the database, but the original file could remain until a cleanup job. Noted for S03 (reindex/cleanup).
- [ASSUMPTION] The store-readiness blocker codes are surfaced as-is in the `store_ready` check.
