## Implementation design

- **Components/modules changed:** +2 Infra/Instagram files; `IChannelProvider` DIM (+4 lines); `WebhookIngressService` (+2 scoped hunks); DI (+2 registrations); 19 unit + 6 integration tests.
- **Runtime or data flow:** POST → size/content-type gates → provider resolve → connection resolve (route → IGID hook → legacy) → active check → HMAC → dedup (app query + unique-index race catch, unchanged) → persist raw → 202/200. Normalization runs async in processing with per-mid InboundEvent dedup (unchanged).
- **Key invariants enforced:** invalid signatures create zero trusted rows; malformed bodies persist raw then DLQ as Permanent (poison path preserved — JsonException propagates); multi-content messages get deterministic unique MessageIds.
- **Compatibility with prior work:** M07 fast-path/dedup untouched; Simulator behavior unchanged (full M07 suites green); no migration.

### Security and isolation impact

- **Tenancy:**
  - Unsigned headers and route IDs can no longer choose the tenant.
  - One account maps to one connection globally.
  - Multi-account deliveries are split, so each raw log is tenant-pure.
  - Normalization ignores foreign entries.
- **Secrets:** the Page token is never decrypted on the Instagram webhook path. `AppSecret` and `VerifyToken` come from environment/user secrets only. Unknown accounts are logged as a 12-hex-character hash. Test fixtures use test-only strings.
- **Idempotency:** event-level keys per connection, an in-batch guard, a unique-index race answered as duplicate at ingress, and recovery that cannot strand an event in `Processing`.

- `[ASSUMPTION]` An unreact payload may omit the emoji (Meta lists `emoji` among reaction fields without stating it is present on `unreact`). Handled by recording the removal with an empty emoji.
- Out of scope: `subscribed_apps` automation, `InstagramGraphOptions.ValidateOnStart`, Compose env pass-through, App Review / business verification.
