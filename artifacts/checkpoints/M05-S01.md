# M05-S01 Checkpoint — Storefront Administration

**Status:** `REVIEW`

## Result

M05-S01 establishes a tenant-owned `Store` aggregate without making any store public or purchasable. Seller administration can create and update a controlled draft, scope canonical published catalog products through `StoreProductPublication`, inspect a computed readiness report, and attempt activation only when all server-owned requirements pass. Delivery and payment remain deliberate blockers until their later M05 boundaries exist.

## Scope completed

- Store lifecycle (`Draft`, `Active`, `Suspended`), globally unique platform slug, controlled default theme, bounded contact/social settings, and plain-text policy fields.
- Tenant-scoped product publication visibility that only counts canonical published products with a published priced variant.
- Seller store, readiness, activation, and publication APIs with tenant permissions, idempotency, optimistic concurrency, safe audit events, and RFC 7807 outcomes.
- PostgreSQL mappings, tenant filters, `xmin` concurrency, partial one-active-store-per-tenant index, command-idempotency table, and forward-only migration `20260904170523_AddStorefrontAdministration`.
- Live OpenAPI snapshot and generated TypeScript contract regeneration.

Deferred exactly as planned: public store resolution, public reads, delivery quotations, payments, cart/checkout, customers, orders, and real storefront administration UI wiring.

## Security and scope review

- Seller endpoints require authenticated identity, verified tenant context, and `storefront.read` or `storefront.write`; Viewer is read-only and PlatformSupport has no Storefront grant.
- Platform slugs are globally unique, but there is no public resolver in this step. Arbitrary host headers and tenant headers cannot serve public store data.
- Audit metadata carries only resource/state data; policy/contact bodies, emails, phone numbers, and idempotency keys are excluded.
- The remaining `postgres:16-alpine` image is referenced by the preserved project PostgreSQL container. It was intentionally not removed.
