## Scope completed

Implemented the deterministic provider simulator and comprehensive integration diagnostics runtime:
1. **Deterministic Provider Simulator Enhancements**:
   - Signature generation helper: `SimulatorChannelProvider.GenerateValidSignature` supporting HMAC-SHA256 and default testing bypass.
   - Configurable latency simulation: parses `X-Simulate-Latency-Ms` in headers and `simulate_latency_ms` in message metadata with bounded `Task.Delay`.
   - Health validation enhancements: evaluates simulated token expiry (`simulate_expired` account or `Expired` connection status), degraded connection states (`simulate_degraded`), revoked states (`simulate_revoked`), and normal/reconnect behavior in `ValidateOrRefreshConnectionAsync`.
   - Synthetic event creation helper: `CreateSignedWebhookRequest` for constructing deterministic signed requests with HMAC signatures, timestamps, and custom headers.
2. **Application Contracts & DTOs**:
   - `IIntegrationDiagnosticsService`: Interface defining `GetOverviewAsync`, `GetConnectionDiagnosticsAsync`, `GetConnectionWebhooksAsync`, `GetWebhookDetailAsync`, and `ExecuteSimulatorScenarioAsync`.
   - Contracts: `IntegrationOverviewDto`, `ConnectionDiagnosticsDto`, `WebhookEventDto`, `WebhookEventDetailDto`, `SimulatorScenarioRequest`, `SimulatorScenarioResult`, `SimulatorScenarioType` enum.
3. **Infrastructure Diagnostics Service**:
   - `IntegrationDiagnosticsService`: Implements `IIntegrationDiagnosticsService` with tenant context enforcement and policy authorization (`IntegrationsRead`, `IntegrationsWrite`).
   - Dynamic 24-hour event/failure aggregation and DLQ counting.
   - ADR-012 Role-Based Payload Redaction: `Owner` and `PlatformSupport` (read-only support) inspect unredacted `RawPayload`; `Admin`, `Operator`, and `Viewer` receive `"[REDACTED]"`.
   - Scenario Runner: Executes deterministic synthetic scenarios (`HealthyInbound`, `DuplicateDelivery`, `OutOfOrderDelivery`, `RateLimit429`, `TransientFailure`, `PermanentPoison`, `TokenExpiry`, `Reconnect`, `DeliveryReceipt`) with tamper-evident audit trail logging.
   - Registered in `DependencyInjection.cs`.
4. **Web API Controller**:
   - `IntegrationDiagnosticsController`:
     - `GET /v1/integrations/diagnostics/overview`: Aggregated status across connections and queues (`IntegrationsRead`).
     - `GET /v1/integrations/connections/{id}/diagnostics`: Detailed connection metrics (`IntegrationsRead`).
     - `GET /v1/integrations/connections/{id}/webhooks`: Paginated webhook event history (`IntegrationsRead`).
     - `GET /v1/integrations/webhooks/{id}`: Single webhook event detail with role redaction (`IntegrationsRead`).
     - `POST /v1/integrations/simulator/scenarios`: Trigger deterministic simulation scenario (`IntegrationsWrite`, anti-forgery, requires `Idempotency-Key`).
     - Retained backward-compatible endpoints: `GET /v1/integrations/webhooks/dead-letter` and `POST /v1/integrations/webhooks/{id}/replay`.

## Security and isolation review

- **Authentication/authorization impact:**
  - All read diagnostic endpoints require `[Authorize(Policy = TenantPermissions.IntegrationsRead)]`.
  - Scenario execution requires `[Authorize(Policy = TenantPermissions.IntegrationsWrite)]` and anti-forgery tokens.
- **Tenant-isolation impact:**
  - Verified via `CrossTenantIsolation_TenantBCannotAccessTenantADiagnostics`: Tenant B cannot view Tenant A connection diagnostics, webhooks, or DLQ items, returning 404 NotFound.
- **Secret/PII/logging impact:**
  - Raw secrets are never returned in any DTO or API response (ADR-013).
  - Webhook payloads are strictly redacted to `"[REDACTED]"` for non-Owner roles per ADR-012.
- **Abuse/idempotency/concurrency impact:**
  - Replay and scenario runner require `Idempotency-Key` headers. Duplicate webhook delivery deduplication is proven in integration tests.
