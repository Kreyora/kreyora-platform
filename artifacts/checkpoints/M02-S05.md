# Checkpoint: M02-S05 — Frontend Contract Adapters and Generated Types

**Date:** 2026-07-28
**Status:** COMPLETE

## Summary

Established the typed frontend-to-API boundary with an OpenAPI-driven contract strategy, a thin HTTP client layer (`apiFetch`), runtime adapter switching based on the `NEXT_PUBLIC_API_URL` environment variable, and a proof-of-connectivity test against the existing `/v1/system/info` endpoint.

## Completed batches

### Batch A — API base client, configuration, and CORS

- Created `apps/web/src/lib/api/api-client.ts` — thin `apiFetch` wrapper with correlation ID forwarding, RFC 7807 error parsing, typed responses, and `Content-Type` management
- Created `apps/web/src/lib/api/errors.ts` — `ApiClientError` class extending `Error` with `status`, `detail`, `correlationId`, and `errors` fields
- Created `apps/web/src/lib/api/index.ts` — barrel export for the API client module
- Updated `apps/web/.env.local.example` with `NEXT_PUBLIC_API_URL` documentation
- Wired CORS middleware in `Program.cs` using `CorsSettings.AllowedOrigins` with exposed headers for `X-Correlation-ID` and `api-supported-versions`

### Batch B — OpenAPI TypeScript codegen

- Installed `openapi-typescript` 7.13.0 as a dev dependency
- Added `generate:api` script to `apps/web/package.json`
- Generated initial TypeScript types from the live OpenAPI spec (currently only `/v1/System/info`)
- Committed the generated `v1.ts` file and the source `openapi-v1.json` spec
- Created `docs/architecture/API_CONTRACT_STRATEGY.md` documenting the transport vs view-model type separation

### Batch C — Runtime adapter switching

- Refactored `ClientProvider` to derive `USING_FIXTURE_ADAPTERS` from `!process.env.NEXT_PUBLIC_API_URL`
- Created `apps/web/src/lib/adapters/api/system-client.ts` — real adapter for `/v1/system/info`
- Created `apps/web/src/lib/adapters/api/index.ts` — barrel export for API adapters

### Batch D — Connectivity proof and tests

- Created `apps/web/src/components/dev/api-status.tsx` — dev-only connectivity proof component
- Created 3 new test files:
  - `api-client.test.ts` — 7 tests for `apiFetch` success/error paths and `ApiClientError` construction
  - `adapter-switching.test.ts` — 2 tests for fixture vs real adapter selection
  - `system-client.test.ts` — 1 test for the system client adapter response parsing
- Extended `SystemEndpointContractTests.cs` with 2 new tests for correlation ID echo and auto-generation

### Batch E — Verification

- `dotnet build` passes with 0 errors, 0 warnings
- `next build` passes with 0 errors
- 63 backend tests pass (36 unit + 6 architecture + 5 contract + 16 integration)
- 494 frontend tests pass (26 test files)
