# Checkpoint: M02-S05 — Frontend Contract Adapters and Generated Types

**Date:** 2026-07-28
**Status:** COMPLETE

## Summary

Established the typed frontend-to-API boundary with an OpenAPI-driven contract strategy, a thin HTTP client layer (`apiFetch`), runtime adapter switching based on the `NEXT_PUBLIC_API_URL` environment variable, and a proof-of-connectivity test against the existing `/v1/system/info` endpoint.

## Completed batches

### Batch A — API base client, configuration, and CORS

- Created `apps/web/src/lib/api/api-client.ts` — thin `apiFetch` wrapper with correlation ID forwarding, RFC 7807 error parsing, typed responses, and `Content-Type` management
- Created `apps/web/src/lib/api/errors.ts` — `ApiClientError` class extending `Error` with `status`, `detail`, `correlationId`, and `errors` fields

- Updated `apps/web/.env.local.example` with `NEXT_PUBLIC_API_URL` documentation
- Wired CORS middleware in `Program.cs` using `CorsSettings.AllowedOrigins` with exposed headers for `X-Correlation-ID` and `api-supported-versions`

- Installed `openapi-typescript` 7.13.0 as a dev dependency

- Committed the generated `v1.ts` file and the source `openapi-v1.json` spec
- Created `docs/architecture/API_CONTRACT_STRATEGY.md` documenting the transport vs view-model type separation

### Batch C — Runtime adapter switching

- Created `apps/web/src/lib/adapters/api/index.ts` — barrel export for API adapters

## Corrective addendum — 2026-08-02: Development-only Scalar API Reference

### Scope completed

Added `Scalar.AspNetCore` 2.16.17 to the Web API and mapped the `Kreyora API` interactive reference at `/scalar` beside the existing Development-only `/openapi/v1.json` endpoint. The route is not mapped outside Development and introduces no authentication scheme, credentials, SMTP provider, Docker Compose service, tenant behavior, or frontend product behavior.

### Design and test coverage

`DevelopmentWebApplicationFactory` creates a fully isolated Development host: it clears database configuration before startup, restores the process environment at disposal, and supplies only non-secret test configuration plus the neutral infrastructure required by the HTTP pipeline. `ScalarEndpointTests` proves that Development returns the Scalar HTML page and the OpenAPI document, while the existing Testing environment returns `404` for both paths.

### Manual reviewer procedure

1. Run `dotnet run --project services/api/src/Kreyora.WebApi/Kreyora.WebApi.csproj --launch-profile http`.
2. Open `http://localhost:5030/scalar`; expect the Kreyora API reference. Open `http://localhost:5030/openapi/v1.json`; expect the same Development OpenAPI document.
3. From the repository root, run `$env:KREYORA_OPENAPI_URL='http://localhost:5030/openapi/v1.json'; corepack pnpm generate:api`, then run `git diff --exit-code -- apps/web/src/lib/api/generated/openapi-v1.json apps/web/src/lib/api/generated/v1.ts`. Expect no diff.
4. Start the API outside Development with valid required configuration; `/scalar` and `/openapi/v1.json` must return `404`.

### Limitation

The Codex command sandbox blocks local TCP port binding, so it could not perform the external-process `localhost:5030` probe or live-fetch generator command. The in-process Development host test exercised the real routes, and deterministic regeneration from the committed OpenAPI snapshot passed. The reviewer procedure above remains required on a normal local machine.
