## Implementation design

- **Data flow (when AI is later used):**
  1. The caller (S06 orchestrator) builds an `AiChatRequest` with a profile.
  2. `ResilientAiChatClient` applies the kill switch, then the data policy, then fake/live.
  3. `OpenAiCompatibleChatClient` → `POST {BaseUrl}/chat/completions`.
  4. The response is mapped to `AiChatResult`; on a transient failure, the request is retried once on the Fallback profile.
- **Invariants:**
  - no provider types in Application (architecture test);
  - personal data never reaches a free tier (start-up validation + per-request check);
  - no prompt, reply, tool-argument or key content in logs (test);
  - failures are values.
- **Compatibility:** no API, schema or migration change. Nothing calls `IAiChatClient` yet (S06/S07). The default configuration keeps the API behaving exactly as before.
