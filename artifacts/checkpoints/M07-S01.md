## Scope completed

Implemented the provider-neutral channel boundary before persistence and webhooks:
1. **Capability Matrix**: Documented 11 capability domains across candidate channels (WhatsApp Cloud API, Instagram Graph API, Messenger Platform, Viber Bot API, Telegram Bot API, and Simulator).
2. **Four Accepted ADRs**:
   - `ADR-010`: Social Connection Ownership and Store Association (Tenant-owned, optional Store binding).
   - `ADR-011`: Normalized Social Event Versioning and Ingress Envelope (`schemaVersion: "v1"` with polymorphic payload).
   - `ADR-012`: Raw Webhook Payload Retention, Redaction, and Privacy (30-day raw body retention with purge).
   - `ADR-013`: Secrets Encryption and Key Management (AES-256-GCM envelope encryption with key versioning).
3. **Domain Layer**:
   - `ChannelType`: Enum covering WhatsApp, Instagram, Messenger, Viber, Telegram, Simulator.
   - `ChannelConnectionStatus`: Pending, Active, Degraded, Expired, Revoked, Disabled.
   - `EncryptedSecret`: Immutable value object holding `CiphertextBase64`, `IvBase64`, `AuthTagBase64`, and `KeyVersion`.
   - `ChannelCapabilities`: Detailed record of capabilities with factory presets (`WhatsAppCloudApi`, `InstagramGraphApi`, `MessengerPlatform`, `ViberBotApi`, `TelegramBotApi`, `FullSimulator`).
   - `NormalizedInboundEvents`: Polymorphic `NormalizedInboundEnvelope` and payloads (`TextMessageReceivedPayload`, `MediaMessageReceivedPayload`, `MessageStatusUpdatedPayload`, `CustomerProfileUpdatedPayload`, `ReactionReceivedPayload`).
4. **Application Layer**:
   - `ISecretEncryptionService`: Interface for symmetric encryption/decryption with key version support.
   - `IntegrationContracts`: Strongly-typed records for `WebhookValidationRequest`, `WebhookValidationResult`, `RawWebhookPayload`, `ChannelConnectionSnapshot`, `OutboundMessageRequest`, `OutboundDeliveryResult`, and `ConnectionHealthResult`.
   - `IChannelProvider`: Channel boundary contract exposing validation, normalization, messaging, and health.
   - `IChannelProviderRegistry`: Provider lookup and discovery interface.
5. **Infrastructure Layer**:
   - `SecretEncryptionOptions`: Options binding with master key and versioned keys support.
   - `AesGcmSecretEncryptionService`: AES-256-GCM authenticated encryption service with key versioning and authentication tag mismatch detection.
   - `ChannelProviderRegistry`: Implementation resolving registered `IChannelProvider` instances by `ChannelType`.
   - `DependencyInjection.cs`: Registered secret encryption and channel provider registry.
6. **Tests**:
   - Unit tests covering `AesGcmSecretEncryptionService`, `ChannelCapabilities`, and polymorphic `NormalizedInboundEnvelope`.
   - Contract tests covering `IChannelProvider` and `ChannelProviderRegistry` with `FakeSimulatorChannelProvider`.

## Implementation design

- **Components/modules changed:**
  - `Kreyora.Domain/Integrations/`
  - `Kreyora.Application/Integrations/`
  - `Kreyora.Infrastructure/Integrations/`
  - `Kreyora.Infrastructure/DependencyInjection.cs`
  - `Kreyora.UnitTests/Integrations/`
  - `Kreyora.ContractTests/Integrations/`
- **Runtime or data flow:**
  - Inbound webhooks will be received as raw payloads, validated against provider secrets using `IChannelProvider.ValidateWebhookAsync`, stored immutably, and normalized into `NormalizedInboundEnvelope` via `IChannelProvider.NormalizeInboundAsync`.
  - Credentials (tokens, secrets) are encrypted before storage using `ISecretEncryptionService.Encrypt`, storing `CiphertextBase64`, `IvBase64`, `AuthTagBase64`, and `KeyVersion`.
  - Channel providers are registered in DI and resolved dynamically via `IChannelProviderRegistry`.
- **Key invariants enforced:**
  - Channel providers expose only provider-neutral contracts; no provider-specific SDK or runtime leaks into application logic.
  - Tenant isolation: inbound envelopes strictly inherit verified `tenantId` and `connectionId`.
  - Secrets are encrypted with AES-256-GCM and never stored or returned in plain text.
- **Compatibility with prior work:**
  - Zero breaking changes to existing order, catalog, storefront, inventory, payment, or notification modules.
  - EF model has 0 pending migrations (DB entities deferred to M07-S02 per plan).

## Security and isolation review

- **Authentication/authorization impact:** No public endpoints introduced in S01.
- **Tenant-isolation impact:** Normalized event envelope strictly binds `tenantId` and `connectionId`. Connection resolution ensures incoming webhooks cannot spoof tenant ownership.
- **Secret/PII/logging impact:** `AesGcmSecretEncryptionService` provides AES-256-GCM encryption with 96-bit nonce and 128-bit authentication tag. Plaintext secrets are never stored or logged.
- **Abuse/idempotency/concurrency impact:** Ingress design requires durable event persistence before processing (to be implemented in S03).
