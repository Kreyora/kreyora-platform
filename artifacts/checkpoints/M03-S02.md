## Amendment — 2026-08-02: antiforgery registration correction

### Cause and correction

A manual local registration attempt returned `500` before account validation because `[ValidateAntiForgeryToken]` requires MVC view-feature filter services, while the host registered only `AddControllers()`. The API now uses `AddControllersWithViews()`; it still maps only API controllers and does not introduce server-rendered UI.

### Evidence

`AuthenticationEndpointTests.Register_WithCsrfToken_InvokesTheAuthenticationService` obtains a real CSRF token/cookie from `/v1/auth/csrf`, posts registration with the token, and verifies `201 Created`. This prevents regression to the missing-filter-service failure.

## Amendment — 2026-08-02: password-reset token provider correction

### Cause and correction

The initial Development password-reset flow generated a token through `UserManager`, but the Identity composition did not register default token providers. `AddDefaultTokenProviders()` is now part of the ASP.NET Core Identity setup, enabling the official token provider used by the later SMTP-delivery amendment.

### Evidence

The subsequent SMTP amendment expands this coverage to delivery, enumeration resistance, expiry, reuse, and safe SMTP failure.

## Amendment — 2026-08-02: SMTP password-reset delivery

### Superseded behavior removed

The browser/API no longer receives `developmentToken`, a local reset link, or a Development-only continuation path. The recovery page always shows the account-enumeration-safe “check your email” message.

### Replacement design and evidence

`IEmailSender` is defined in Application and MailKit-backed `SmtpEmailSender` is implemented in Infrastructure. `AuthenticationService` asks Identity for the official token, builds a configured public `/recover/reset` URL, and sends HTML plus plain-text email. It catches SMTP failures without returning or logging secret, recipient, token, or provider details. `AuthController` always returns the same `202 Accepted` response.

`AuthenticationServiceTests` covers known/unknown email behavior, generated URL content, invalid/expired/reused token rejection, and credential-safe SMTP failure. `AuthenticationEndpointTests` verifies the same token-free response body for distinct email values. `SmtpEmailSenderTests` starts a controlled Mailpit Testcontainers inbox, sends through real MailKit SMTP, and reads the captured message back. This verifies the transport without sending an uncontrolled external email.

Configuration and operator instructions are in `docs/architecture/LOCAL_EMAIL_DELIVERY.md`. ADR-004 supersedes the Development token-return paragraph in ADR-002; the cookie-session decision remains unchanged.
