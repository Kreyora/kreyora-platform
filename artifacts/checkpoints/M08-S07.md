## Implementation design

- **Components changed:**
  - `SimulatorChannelProvider` (constructor flag + `AcceptsFixedTestSignatureIn`) and its DI registration;
  - the `Program.cs` auth limiter policies + `ClientPartition`;
  - `HangfireSetup` (server switch);
  - `InstagramGraphClient` (throttle and window mapping);
  - `scripts/sandbox/*`; the readiness document.
- **Live data flow observed:**
  1. Meta → cloudflared → allowlist proxy → `POST /v1/webhooks/instagram`.
  2. App-Secret HMAC check → event stored (deduplicated) → processing job → conversation and message.
  3. Inbox reply → outbox → delivery job → `POST /me/messages` → Sent.
  4. Meta's echo is deduplicated and merged.
- **Key invariants enforced:**
  - Only the webhook route was internet-reachable.
  - Deliveries with a wrong signature were refused (3 × 401).
  - A duplicate delivery produced no second record.
  - The token was validated live before it was stored encrypted.
  - Evidence is aggregate only.
- **Compatibility:**
  - No API contract change, no migration.
  - Simulator connections outside Development/Testing now need a real HMAC secret; this is intended.
