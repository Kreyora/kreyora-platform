## Implementation design

### Data flow

- **Store data**: Loaded once in layout via `StorefrontClient.getStore(DEMO_TENANT_ID)`, passed to `StoreHeader` and `StoreFooter` as props
- **Cart state**: React Context (`CartProvider`) at the layout level, consumed by `StoreHeader` (count badge), PDP (add), cart page (display/modify), checkout (items/subtotal/clear)
- **Product browsing**: `CatalogClient.listProducts()` and `getCollections()` for home/collection pages; `getProduct()` + `InventoryClient.getInventory()` for PDP
- **Checkout flow**: Cart items → `CheckoutClient.createQuote()` → `CheckoutClient.submitOrder()` → redirect to confirmation → `OrderClient.getOrder()` for display
- **Order lookup**: `OrderClient.listOrders({ search })` for searching by order number

### Key design decisions

1. **Cart as client state**: No port method for `addToCart` — cart is purely client-side React state. This aligns with the demo scope where persistence isn't needed.
2. **Single-tenant shortcut**: `DEMO_TENANT_ID` constant maps the route `[slug]` to the fixture tenant. The `slug` param is used for URL construction but store data is always loaded for "tenant-namaste-crafts".
3. **Duplicate-submit protection**: The checkout maintains both `submitting` (loading state) and `submitted` (permanently disabled) flags to prevent double submission.
4. **Mobile-first**: All layouts use `grid-cols-2` base with `sm:grid-cols-3` and `lg:grid-cols-4` enhancements. Checkout uses single-column on mobile, 3-column grid on desktop with summary sidebar.
5. **Quiet checkout motion**: No entrance animations in checkout — only functional transitions (focus, hover). Matches the prompt requirement for quieter checkout.

## Risks and known limitations

1. **No real images**: Product gallery shows placeholder SVGs. Actual image display requires either fixture image files or a CDN integration.
2. **Single-tenant only**: The `DEMO_TENANT_ID` constant hardcodes the tenant. Multi-tenant storefront routing will need a slug-to-tenant resolution service.
3. **No cart persistence**: Cart state is lost on page reload. localStorage persistence could be added but is unnecessary for the demo.
4. **No price validation**: The checkout trusts client-side subtotal for display but correctly delegates fee calculation to the `createQuote()` port.
5. **No QR proof upload**: The merchant QR payment option shows a QR placeholder but has no file upload simulation. The prompt mentions "QR proof simulation if enabled" — this is deferred to be a visual placeholder only.
6. **Order lookup**: Only finds orders by exact/partial order number match against the 3 fixture orders. A real implementation would need authenticated customer sessions.
