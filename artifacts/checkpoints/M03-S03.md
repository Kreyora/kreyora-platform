## Scope completed

Implemented verified per-request seller tenant selection through `X-Kreyora-Tenant-Id`. The server treats the header only as a selection hint, verifies active authenticated membership plus active tenant state, creates a scoped context, and clears it after every request. Added context-aware persistence, durable job/outbox propagation primitives, tenant-prefixed future storage/cache/search key builders, the tenant-owned outbox migration, and M03-S03 tests.

The stale handoff was reconciled: M03-S01 and M03-S02 are `APPROVED`, M03-S02 has a clearly labelled reconstructed evidence report, and M03-S03 is the active review step.

## Implementation design

- **Components/modules changed:** Application contracts define tenant context, resolver, scoped query service, key builder, job envelope/runner, and outbox processor. Infrastructure resolves PostgreSQL memberships, manages scopes, scopes queries, enforces writes, and builds tenant-prefixed keys. Web API middleware establishes verified context only for marked endpoints.
- **Runtime/data flow:** An authenticated request to `[RequireTenantContext]` must include one ULID-shaped tenant ID. Middleware resolves it against active membership/tenant, opens a scope, invokes the endpoint, then disposes the scope. Tenant jobs/outbox work resolve an active persisted tenant ID before opening their scopes.
- **Key invariants enforced:** Header is never authority. Missing/malformed selection is `400`; foreign, revoked, suspended, or inactive selection is `403`; tenant-owned writes require matching context; outbox reads use a global filter as defense in depth; raw SQL still needs an explicit tenant predicate.
- **Compatibility:** Auth/public endpoints remain tenant-neutral. Fixture-backed seller UI remains unchanged. Existing durable M02 outbox rows become inaccessible rather than being assigned a fabricated system tenant.

## Security and isolation review

- **Authentication/authorization impact:** Tenant-scoped endpoints derive authority from Identity principal plus live membership and tenant state; the client header cannot bypass either check.
- **Tenant-isolation impact:** Context is per request/per durable operation and disposed after use. Outbox filtering, write enforcement, scoped query helper, raw-query test, and key prefixes overlap as defenses.
- **Secret/PII/logging impact:** No secrets, credentials, or provider configuration are added. The new code does not log tenant IDs.
- **Abuse/idempotency/concurrency impact:** Existing idempotency primitives remain. Job/outbox runners reject unavailable tenants rather than executing with stale scope.
