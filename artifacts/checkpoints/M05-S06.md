## Scope completed

M05-S06 replaces the public storefront's runtime use of seller/fixture ports with separate typed public ports. In live mode, storefront reads, quotes, checkout sessions, and COD orders use the M05-S05 generated anonymous API contract; fixture mode remains an explicit adapter selection only. The frontend does not fall back to fixtures after a live request fails.

The cart is scoped to the storefront slug and persists only non-PII cart intent in session storage. Checkout uses the authoritative quote → checkout-session → COD-order sequence with stable idempotency keys, conflict/rate-limit recovery, and safe confirmation data. Merchant QR, payment proof, public order lookup, seller order operations, and M06 work were not started.

## Implementation design

- **Components/modules changed:** Added public storefront/checkout ports, generated-contract API adapters, matching fixture adapters, public view models, dynamic storefront shell, and adapter tests. Rewired catalog, product, cart, checkout, confirmation, collection, and lookup routes.
- **Runtime/data flow:** Development with `NEXT_PUBLIC_API_URL` uses `/public/v1/dev/stores/{slug}`. Host-bound deployments use relative `/public/v1/store` paths and omit browser credentials. Product media uses the verified public media endpoint. The generic HTTP client now preserves `201` JSON and exposes `Retry-After` through `ApiClientError`.
- **Key invariants enforced:** No public page calls seller inventory, order, delivery-rule, payment-method, or tenant-selection APIs. Checkout never calculates trusted delivery/total/payment facts in the browser; it displays server quote/session/order values. A live error remains a live error. Session/order retries preserve their idempotency keys.
- **Compatibility with prior work:** M05-S05's OpenAPI-generated types are consumed without backend/API/schema changes. Existing seller ports continue unchanged. The legacy fixture experience remains available only when the public fixture mode is explicitly selected.

## Security and isolation review

- **Authentication/authorization impact:** Public adapters explicitly omit credentials and use no seller/tenant header. Seller authorization remains server-side and unchanged.
- **Tenant-isolation impact:** Store selection stays solely on M05-S05 host/dev-slug resolution. UI passes a slug only to the sanctioned local dev route; host-bound requests send no slug selector.
- **Secret/PII/logging impact:** Cart session storage excludes contact/address, quote tokens, sessions, idempotency keys, and order details. Confirmation storage contains only the safe public confirmation projection.
- **Abuse/idempotency/concurrency impact:** Checkout reuses stable idempotency keys per unresolved write, prevents duplicate submit while pending, retains cart on failure, and exposes safe `429` retry timing. Server rate limits/reservation correctness remain verified by the M05-S05 integration regression.

## Reviewer procedure

1. Start Docker Desktop, then run `docker compose up --build` from the repository root with a seeded active, purchase-ready Store, a visible published product, stock, and an active COD delivery rule.
2. Set `NEXT_PUBLIC_API_URL=http://localhost:5001` for local development. Open `/store/{slug}` and confirm browser traffic uses only `/public/v1/dev/stores/{slug}` paths—no seller endpoint or tenant header.
3. At 375 px and desktop width: browse a product, add it to cart, calculate delivery, accept privacy acknowledgement, and place one COD order. Confirm that quote and confirmation totals match the API response.
4. Change address/cart after a quote, expire a quote/session, or send a duplicate click. Confirm cart retention, re-quote behavior, disabled pending submit, and no duplicate order.
5. Confirm merchant QR/payment options, exact stock, SKU, seller delivery rules, and seller order data are absent from live public UI.
6. Review the verification commands above. M05-S06 is approved; M05-S07 verification is now in progress.
