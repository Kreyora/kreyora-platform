## Scope completed

Implemented the persistent connection model, encrypted-secret lifecycle, authorized metadata flows, and PostgreSQL migration:
1. **Domain Aggregate Root**:
   - `ChannelConnection`: Entity inheriting from `BaseEntity, ITenantOwned` with `TenantId` ownership, optional `StoreId` binding, `ChannelType`, `ExternalAccountId`, `DisplayName`, `Status`, `EncryptedCredentials`, `Capabilities`, expiry timestamps, and health summary.
   - Domain methods: `Create`, `UpdateMetadata`, `UpdateCredentials`, `RotateSecret`, `UpdateHealth`, `Disable`, `Enable`, and `Revoke`.
2. **Persistence & Migration**:
   - `ChannelConnectionConfiguration`: EF Core entity configuration for `channel_connections` table.
   - Mapped `EncryptedCredentials` as owned entity (`credentials_ciphertext`, `credentials_iv`, `credentials_auth_tag`, `credentials_key_version`).
   - Mapped `Capabilities` as `jsonb` column.
   - Shadow `xmin` concurrency token.
   - Unique composite index: `(TenantId, Channel, ExternalAccountId)`.
   - Foreign key to `Store` with `DeleteBehavior.Restrict`.
   - EF Core Migration: `20260919185315_AddChannelConnections.cs` generated and verified clean against model.
   - `AppDbContext`: Added `DbSet<ChannelConnection> ChannelConnections` with global query filter `c => c.TenantId == CurrentTenantId`.
3. **Application Contracts & DTOs**:
   - `IChannelConnectionService`: Interface defining authorized connection operations.
   - `ChannelConnectionDto`: Strictly redacted DTO exposing only public metadata, capabilities, status, and health summary. Plain text secrets, ciphertexts, IVs, and auth tags are strictly excluded.
   - `CreateChannelConnectionRequest` and `UpdateChannelConnectionRequest`.
4. **Infrastructure Service**:
   - `ChannelConnectionService`: Implemented with `ITenantPermissionAuthorizer` enforcement (`TenantPermissions.IntegrationsWrite` for mutations, `IntegrationsRead` for queries), AES-256-GCM encryption at rest via `ISecretEncryptionService`, zero-downtime key rotation hook (`RotateConnectionSecretsAsync`), and audit trail recording via `IAuditEventService`.
   - Registered in `DependencyInjection.cs`.
5. **Web API Controller**:
   - `ChannelConnectionsController`: Under `v1/integrations/connections` exposing CRUD, rotate-secret, disable, enable, and health endpoints with policy authorization.
6. **Tests**:
   - 12 unit tests in `ChannelConnectionTests.cs` (aggregate creation, validation, status transitions, secret rotation, invariant guards).
   - 8 integration tests in `ChannelConnectionIntegrationTests.cs` against real PostgreSQL in Docker (Testcontainers) covering encryption at rest, DTO redaction, key rotation, cross-tenant isolation, duplicate account rejection, store binding validation, lifecycle transitions, and RBAC authorization.

- **Runtime or data flow:**
  - Merchants create connections by supplying external account credentials in plain text over HTTPS.
  - The application service immediately encrypts the secret using `ISecretEncryptionService.Encrypt(plainText)` with AES-256-GCM, storing `CiphertextBase64`, `IvBase64`, `AuthTagBase64`, and `KeyVersion`.
  - Plain text credentials are never persisted or returned. Queries return `ChannelConnectionDto` with `HasCredentials: true` and `KeyVersion: "v1"`.
  - Key rotation can be executed at any time via `RotateConnectionSecretsAsync(connectionId, targetKeyVersion)`, which decrypts the existing secret with its recorded key version and re-encrypts with the target key version.
  - Inbound and outbound operations resolve connections through `AppDbContext` where global query filters guarantee tenant isolation.
- **Key invariants enforced:**
  - Mandatory tenant scoping (`TenantId`), with optional `StoreId` binding per ADR-010.
  - Uniqueness constraint: `(TenantId, Channel, ExternalAccountId)` prevents duplicate external channels within a tenant.
  - Secrets encrypted at rest (ADR-013) with zero plaintext leakage in database, DTOs, or logs.
  - Policy RBAC: Only Owner and Admin can perform mutations; Operator and Viewer have read-only access.
- **Compatibility with prior work:**
  - Additive schema migration with 0 pending model changes.
  - Compatible with existing `Store`, `AuditEvent`, and tenant authorization infrastructure.

## Security and isolation review

- **Authentication/authorization impact:** All endpoints require authenticated tenant session (`RequireTenantContext`). Mutations require `TenantPermissions.IntegrationsWrite` (Owner, Admin only); queries require `TenantPermissions.IntegrationsRead`.
- **Tenant-isolation impact:** Global query filter `c => c.TenantId == CurrentTenantId` enforces tenant boundary on all queries. Cross-tenant queries or mutations return 404 Not Found.
- **Secret/PII/logging impact:** Secrets are encrypted at rest with AES-256-GCM. `ChannelConnectionDto` strictly redacts plaintext secrets and encrypted envelopes. Logging explicitly excludes credentials.
- **Abuse/idempotency/concurrency impact:** Shadow `xmin` concurrency token prevents lost updates. Unique index `(TenantId, Channel, ExternalAccountId)` prevents duplicate connection collisions.

## Decisions and assumptions

- **ADRs created or changed:** Follows accepted `ADR-010` (connection ownership) and `ADR-013` (secrets encryption).
- **Assumptions made:** Connections can be created without credentials in pending state, or with credentials in active state. Store binding is optional.
- **External evidence used:** Meta WhatsApp Business API and Instagram Messaging API credential requirements.
