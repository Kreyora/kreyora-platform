## Scope completed

Implemented the approved plan `docs/plan/M08-S04_CONVERSATIONS_MESSAGES_PLAN.md` (owner approval 2026-10-05, "implement"):

1. **Domain:**
   - `CustomerChannelIdentity` (Customers module) and `Conversation`, `Message`, `MessageReaction`, `ConversationLabel` (new Conversations module).
   - Enums for status, automation mode, direction, origin, and kind.
   - The M05 checkout `Customer` is unchanged.
2. **ADR-016 rules:**
   - one identity per `(connection, provider user)`;
   - one thread per `(connection, identity)`, starting `New` + `Automated`, with the store copied from the connection;
   - `Resolved`/`Closed` reopen to `New`; `Spam` stays silent;
   - max-timestamp counters; read watermark; monotonic outbound delivery; reaction last-write-wins.
3. **Ingestion:**
   - `IConversationIngestionService` is called by `WebhookProcessingService` for each newly created `InboundEvent`, before the single `SaveChanges`, so it is atomic with the inbound event.
   - Lookups check pending (unsaved) entities first, so several events in one delivery for a new customer work.
4. **Read API:** `ConversationsController` with
   - `GET /v1/conversations` (paged; filters status/connection/unread/assignee),
   - `GET /v1/conversations/{id}`,
   - `GET /v1/conversations/{id}/messages` (keyset `before` cursor),
   - `POST /v1/conversations/{id}/read` (antiforgery-protected).
5. **Privacy:** `IConversationPrivacyService.EraseIdentityAsync`.
   - Owner only; redacts message text and media URLs, clears the display name, removes the identity's reactions.
   - Audited with counts-only metadata; idempotent.
   - Service-level only; no HTTP endpoint in S04.
6. **Contract:** OpenAPI snapshot and TypeScript client regenerated from a live local API.

Not done (as planned): staff reply, assignment/label edits, takeover, 24-hour window (S05); echo messages (S05); profile-name lookup (S05/S07); inbox UI (S06); media download to R2.

## Implementation design

- **Components/modules changed:**
  - New Conversations module across Domain/Application/Infrastructure/WebApi.
  - Customers module gains `CustomerChannelIdentity`.
  - `WebhookProcessingService` gains one optional dependency and one call site.
- **Runtime or data flow:**
  1. Signed webhook → ingress (S03) → `WebhookEvent`.
  2. Processing → normalize → per new `InboundEvent`: ingestion finds or creates identity and conversation, then appends the message, or applies the receipt or reaction.
  3. Single `SaveChanges`, then the inbox API reads tenant-filtered projections.
- **Key invariants enforced:**
  - Uniqueness on: identity `(connection_id, external_user_id)`; conversation `(connection_id, customer_channel_identity_id)`; message `(connection_id, provider_message_id)`; reaction `(connection_id, provider_message_id, reactor_channel_id)`.
  - Composite tenant foreign keys (`tenant_id`, id): identity → conversation → message/label.
  - `xmin` concurrency tokens; timeline ordered by provider time.
  - Concurrent first contact resolves through the unique index plus the S03 recovery/retry (observed in the test run: the first pass lost the race, the retry processed it).
- **Compatibility with prior work:**
  - `WebhookProcessingService`'s new constructor parameter is optional and appended last. Existing M07 tests that construct the service without it are unaffected; production DI supplies it.
  - The Simulator and M07 suites are unchanged and green.

## Security and isolation review

- **Authentication/authorization:**
  - `conversations.read` (Viewer+) for reads; `conversations.write` (Operator+) plus antiforgery for mark-read.
  - Erasure is Owner only (explicit role check; read-only PlatformSupport denied).
  - Tested over HTTP:
    - unauthenticated → `401`;
    - Viewer `POST` → `403`;
    - missing CSRF token → `400`, with no state change;
    - Operator mark-read → `200`.
- **Tenant isolation:**
  - Every query filters by `TenantId` explicitly, in addition to the EF filters.
  - Another tenant's conversation ID returns `404` on detail, messages, and mark-read, and never appears in lists.
  - The same provider user ID on two tenants' connections gives two separate identities.
  - Composite tenant foreign keys.
- **Secret/PII/logging:**
  - Stored fields are limited to: provider user ID, optional display name, message text/media URL/type, and timestamps.
  - No profile pictures, usernames, phone numbers, or raw payload copies; raw payloads stay under ADR-012.
  - Responses exclude provider user IDs, reactor IDs and raw payloads (asserted); the customer label is masked to the last 4 characters.
  - Logs carry connection and inbound-event IDs only; erasure audit metadata holds counts only (asserted).
- **Abuse/idempotency/concurrency:**
  - ADR-015 event keys plus unique indexes plus `xmin` plus the S03 retry.
  - Atomicity proven: an injected ingestion failure leaves zero `InboundEvent`/identity/conversation rows and the event `Failed`; the retry then succeeds.
