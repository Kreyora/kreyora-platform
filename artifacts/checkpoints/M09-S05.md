## Scope completed

Implemented `docs/plan/M09-S05_CONTROLLED_WRITE_TOOLS_PLAN.md` (approved 2026-10-07, "ok implement"; Q1–Q9 as recommended). Nothing in this step calls a model.

1. **ADR-020, the AI action permission matrix** (`Proposed`; your acceptance is part of this review). Five write tools exist; nothing else with side effects does.
2. **QuoteCart** (Q1, no order drafts):
   - resolves the customer's place (zone names + gazetteer) to the matched zone and prices through the existing storefront quote service;
   - returns lines, delivery fee, total, ETA, COD and a `quoteId`. The signed quote stays on the server.
3. **ReserveInventory / ReleaseReservation** (Q3, Q4):
   - 15-minute chat holds through a new system entry point on `InventoryService`: same row locks, serializable retries, expiry, idempotency commands and audit as checkout; `Source = Conversation`;
   - **two-phase confirmation**: the first call returns a summary + `confirmationId` and holds nothing; the second call holds only if **a customer message arrived after the proposal** (checked by the server) and the items are identical;
   - **limits**: ≤ 5 lines × 5 units, one hold per item per chat (no stacking), ≤ 10 holds per chat per 24 h;
   - release touches only this chat's active holds.
4. **CreateCheckoutLink** (Q2):
   - saves a link: random token, **only its SHA-256 stored**, 24 h, ≤ 5 live per chat;
   - returns `{storefront}/store/{slug}/link/{token}`;
   - optional `quoteId`: the link must match the quote's items at still-current prices, otherwise `stale`.
5. **Storefront side:**
   - public `GET …/assistant-links/{token}`: current prices and availability, no customer data, `Cache-Control: no-store`;
   - a landing page that fills the cart and opens the normal checkout;
   - checkout sends the token with the quote and the session.
6. **Hold handover and order linking:**
   - **quote:** the chat's own held units count as available to the customer with the link (everyone else still sees them reserved);
   - **checkout session:** inside the existing serializable transaction, the chat's holds are released **before** revalidation and re-reserved for checkout (the last unit can't be lost in between);
   - **order:** marks the link used. Order-status lookups for that chat then show it without verification, and the chat identity is linked to the customer when the customer saved their contact details.
7. **EscalateToHuman** (Q7):
   - system takeover through `Conversation.TakeOver()` + ADR-017 automation suppression;
   - the reason category (fixed list) is stored on the conversation, shown in the conversation detail API, and audited without customer text;
   - idempotent; a staff hand-back clears it.
8. **Registry v2** (`kreyora-tools.v2`):
   - write tools need a conversation; after a human takeover they return `automation_paused` (escalation still answers);
   - seller preview dry-runs them (QuoteCart runs for real; it writes nothing);
   - **duplicate calls in the same turn replay the first result** (key = tenant + conversation + turn + tool + canonical arguments).
9. **Policy (Q9):**
   - write tools are now selectable; new shops get QuoteCart + CreateCheckoutLink, with holds opt-in;
   - `CreateOrderDraft` is removed;
   - existing policies are unchanged.

**Deviations from the plan:**
- **D1:** order linking also works **without** a saved customer. The storefront checkout sends `saveContact: false`, so no customer record exists. Lookups therefore also recognize orders placed through this chat's own checkout links; the identity → customer link is set only when a customer record exists.
- **D2:** the quote service gained an optional hold allowance, and the checkout session releases holds **before** revalidation (the plan said "inside the transaction", without the order). Found by the end-to-end test: otherwise the customer's own hold blocked their quote and checkout.
- **D3:** the hold length reuses `Inventory:Reservations:DefaultDurationMinutes` (15), not a new `Ai:Tools:HoldMinutes`.
- **D4:** "an identical live link is returned instead of a new one" is not implemented. The raw token isn't stored, so it can't be returned again. Same-turn duplicates replay; across turns the per-chat link cap applies.
- **D5:** the registry version moved to `kreyora-tools.v2`, because the tool set changed. S04 tests updated.

## AI action permission matrix (ADR-020) — for your approval

| Tool | May | Can never | Limits | Confirmation | Audit |
|---|---|---|---|---|---|
| QuoteCart | Price items + delivery | Change prices; quote hidden/unpublished/out-of-stock items | 10 lines × 5 | — | — (replay record) |
| ReserveInventory | Hold this chat's items 15 min | Hold for others; exceed stock | 5 lines × 5; 1 per item; 10/day | Two-phase, server-checked | `inventory.reservation.created` |
| ReleaseReservation | Release this chat's holds | Touch checkout/staff/other chats' reservations | Own only | — | `inventory.reservation.released` |
| CreateCheckoutLink | Cart-filled storefront link | Create orders; set customer details; choose payment; mark paid | 10 lines × 5; 24 h; 5 live | Customer confirms at checkout | `assistant.checkout_link.created` / `.used` |
| EscalateToHuman | System takeover + category | Release takeover; act afterwards | Idempotent | — | `assistant.escalated` |

**Not available to the AI at all:** mark paid, verify payment, confirm/fulfil/cancel orders, change prices or stock, publish, discounts, refunds, staff actions (tested: these names return `tool_not_allowed`).

## Implementation design

- **Domain:**
  - `Assistant/AssistantActions.cs`: `AssistantCheckoutLink`, `AssistantAction` (proposals + completed replays);
  - `Conversation.Escalate` / escalation fields;
  - `CustomerChannelIdentity.LinkCustomer` (erasure unlinks);
  - policy tool lists.
- **Application:**
  - `Assistant/AssistantWriteContracts.cs`: write services, link service, handover, escalation categories;
  - `IConversationInventoryHoldService`, `IConversationHoldAllowance`, `IConversationEscalationService`;
  - quote request and checkout session request gain optional link/conversation fields.
- **Infrastructure:**
  - `Assistant/AssistantWriteServices.cs`: action store, cart validator, quote, hold and link services (+ handover), hold allowance;
  - `Assistant/Tools/WriteTools.cs`; registry v2;
  - `InventoryService` hold entry points;
  - `ConversationEscalationService`;
  - optional hooks in `StorefrontQuoteService`, `CheckoutSessionService`, `OrderCreationService` (null-safe defaults keep existing callers unchanged).
- **WebApi:** public link route; quote and session requests carry the link token.
- **Web:** port/adapters (`getAssistantLink`, token on quote/session), `useCart.replaceItems`, `lib/storefront/assistant-link.ts`, landing page `store/[slug]/link/[token]`, checkout wiring.
- **"Can't bypass normal APIs":**
  - the tools call only the services the public storefront and staff paths use: quote service, inventory locking/expiry/audit, checkout session, order creation, takeover;
  - the link only pre-fills a cart; the normal checkout revalidates price, stock, publication and payment rules.

## Security and isolation review

- **Context:** tenant, store, conversation and customer identity come from the server; arguments are lookup keys; unknown fields are rejected.
- **Authorization:** policy allowlist per tool (holds opt-in); conversation-only; takeover gate; preview dry-run; console preview stays Owner/Admin.
- **Integrity:**
  - every write goes through the existing commands (locks, serializable transactions, idempotency commands, audit);
  - checkout revalidates; the link never carries prices or customer data;
  - confirmations are server-checked and single-use.
- **Privacy:**
  - the AI never collects contact details (the customer types them on the storefront), consistent with ADR-018's synthetic-only rule for free tiers;
  - link tokens are random and stored hashed; the public read has no PII and is not cached;
  - audit metadata carries IDs, counts and categories only;
  - erasure unlinks the identity.
- **Abuse limits:** per-line and per-chat caps, daily hold cap, live-link cap, 24 h link expiry, 15 min holds (expired by the existing job).
