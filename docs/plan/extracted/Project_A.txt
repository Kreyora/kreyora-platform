Core Database Entities & Relationships
The database engine serves as the absolute application source of truth.
	•	Seller: Represents a tenant inside the multi-tenant system.
	•	SocialChannel: Stores encrypted tokens for integrated channels (WhatsApp, Instagram, Facebook).
	•	Product / ProductVariant: Handles multi-attribute item catalogs.
	•	Inventory / InventoryReservation: Manages stock balances with pessimistic/optimistic concurrency locking.

Core Security & Reliability Matrix
	•	Multi-Tenant Data Isolation: Implemented via global query filters on the EF Core DbContext to prevent tenant cross-contamination.
	•	Data Security: Encryption for all active social platform API credentials and access tokens.
	•	Idempotency Safeguards: Unique constraint verification on message IDs to filter out duplicate incoming webhook events.
	•	Concurrency Integrity: Database row locks activated during reservations to block artificial inventory overselling.
File 3: Execution Roadmap & AI Prompt Matrix
Use this sequence of structured engineering prompts to direct your AI coding assistant (such as Cursor, ChatGPT, or Gemini) through building your application step by step.
Phase 1: Solution Initialization & Multi-Tenant Core
Prompt 1: Project Scaffolding

Context: Building an AI-powered social commerce application using .NET 10.

Task: Generate a production-grade .NET 10 solution structure using Clean Architecture, Domain-Driven Design (DDD), and CQRS. Set up four distinct projects: Domain, Application, Infrastructure, and WebApi. Implement the standard folder layout for each project, including common folders for entities, interfaces, commands, queries, persistence configurations, and api controllers. Provide a concise textual architectural tree diagram mapping out this structure.
Prompt 2: Tenant Isolation & Database Layer

Context: The database is PostgreSQL utilizing Entity Framework Core, requiring absolute multi-tenant data isolation and audit logging.

Task: Write a base multi-tenant application layout using Finbuckle.MultiTenant or a custom EF Core filter. Generate the Seller entity representing a tenant. Create a custom ApplicationDbContext that intercepts SaveChanges to automatically inject the correct Tenant Identifier into entities implementing an IMustHaveTenant interface. Include configuration boilerplate for standard ASP.NET Core Identity authentication and Role-Based Access Control (RBAC).
Phase 2: Inventory, Catalog, & Transaction Management
Prompt 3: Catalog and Concurrency-Safe Inventory

Context: Implementing the product management engine.

Task: Generate the core database model classes, Fluent API mappings, and MediatR handlers for the following entities: Product, ProductVariant, Inventory, and InventoryReservation. Write a MediatR command for ReserveInventoryCommand that uses pessimistic or optimistic database concurrency locking to guarantee that an item cannot be double-reserved by concurrent client chats.
Prompt 4: Order Creation Engine

Context: Transitioning a successful customer chat interaction into a concrete sale transaction.

Task: Implement the Order and OrderItem aggregate structures alongside a state management machine. Create a MediatR handler for a CreateOrderCommand. The tool must enforce a strict business rule rule: the AI can never guess or hallucinate product details or inventory state; it must validate inventory and fetch real-time prices directly from the application database services before saving the order.
Phase 3: Social Channel Abstractions & Webhook Ingestion
Prompt 5: Channel Integration Architecture

Context: Integrating external chat streams (WhatsApp, Instagram, Facebook Messenger) into a single operational interface.

Task: Design a clean, decoupled social messaging interface structure. Write an abstract ISocialChannelProvider contract with operations for sending text messages, media documents, and product carousel links. Implement a concrete layout structure for a MetaChannelProvider targeting the Meta Graph API. Ensure all stored platform authorization tokens are treated as sensitive data and properly encrypted.
Prompt 6: Webhook Ingestion & Idempotent Processing

Context: Ingesting high-volume chat streams without missing events or introducing duplicates.

Task: Create a WebhookController to act as an entry point for inbound Meta message callbacks. Implement standard webhook signature validation middleware. To ensure reliability, when a webhook message is verified, immediately save the raw request event data payload to a processing store and return an HTTP 200 OK status to the provider. Then, use Hangfire to schedule a decoupled background worker job (ProcessInboundMessageJob) to process the conversation. Enforce strict message idempotency using unique constraint checks on the provider message ID.
Phase 4: AI Orchestration Layer & RAG Knowledge Base
Prompt 7: Tool Calling Orchestration Engine

Context: Building the core AI brain using external LLM APIs (such as OpenAI or Gemini SDKs).

Task: Create an AI orchestration system that maps incoming user messages into structured intent actions via tool calling. Explicitly register the following application tool functions as capabilities exposed to the LLM model: SearchProducts, CheckInventory, GetPrice, GetShippingInfo, CreateOrder, ReserveInventory, and EscalateToHuman. Write the routing block that interprets the LLM's chosen tool call signature, maps it to the corresponding application MediatR command or query, executes it against the database, and returns the response to the AI assistant. Append an execution history into AIActionLog for audit tracking.
Prompt 8: Knowledge Base RAG Engine

Context: Empowering the AI agent to answer complex context questions regarding merchant store shipping, FAQs, and refund procedures.

Task: Build a Retrieval-Augmented Generation (RAG) feature set. Define the KnowledgeDocument schema for storing seller contextual data. Implement a service that maps incoming user text into text embeddings, processes vector similarity lookups to extract context blocks, and injects those highly relevant passages directly into the LLM system prompt prior to executing the tool-calling loop.
Phase 5: Verification, Operations, & Deployment Layouts
Prompt 9: Comprehensive Integration & Unit Testing Suite

Context: Verifying system data handling, multi-tenant boundaries, and concurrency constraints before launch.

Task: Create a companion testing project using xUnit, Moq, and FluentAssertions. Write unit test cases verifying that multi-tenant database queries filter out data from unrelated tenants. Write an integration test utilizing WebApplicationFactory that simulates a high-concurrency webhook block executing the ReserveInventoryCommand simultaneously to verify that row-locking mechanisms properly prevent stock over-allocation.
Prompt 10: Production Deployment Scaffolding

Context: Packaging the modular monolith for automated, low-cost cloud deployment using Docker and CI/CD tools.

Task: Write a multi-stage Dockerfile optimized for building and running an ASP.NET Core .NET 10 Web API. Create a complete GitHub Actions or alternative CI/CD configuration YAML file that automatically runs the test suite, builds the container image, maps configuration variables, and handles automated database migrations during deployment. Include boilerplate code sections for centralized application logging, standard container health check endpoints, and structured exception logging.
